## 题面（可直接粘贴到 OJ 题目描述）

**题目描述**

一个 agent 回答问题时可以选择"直接回答"或"调用工具后回答"。本题实现这条流水线的两个确定性核心：

1. **CALC（工具本体）**：一个白名单安全计算器。给定一个整数四则运算表达式，输出其值；表达式非法时输出规定的结构化错误码。不允许使用 `eval`/`exec` 或调用外部程序。
2. **ROUTE（离线批次路由）**：给定一批题目，每题带有调用前即可算出的"工具需求分数"，在严格的调用预算内选出最值得调用工具的题目，并对结果对账。

**计算器规则**

- 文法：`expr := term (('+'|'-') term)*`；`term := factor (('*'|'/') factor)*`；`factor := 整数 | '(' expr ')' | '-' factor`；
- 整数字面量为非负十进制整数；一元负号可以连用（`--3` 等于 3）；**没有一元加号**（`1++2` 是语法错误）；
- 空格和制表符可出现在任意位置，无语义；
- `+`/`-` 左结合（`10-2-3 = 5`）；`/` 为**向零取整**的整数除法（C 语义：`-7/2 = -3`，`7/-2 = -3`；注意 Python 的 `//` 是向下取整，不要直接用于负操作数）；
- 错误码（按此顺序检查，靠前优先）：
  | 错误码 | 含义 |
  | --- | --- |
  | `ERR_EMPTY` | 表达式为空或全是空白 |
  | `ERR_TOO_LONG` | 原始表达式长度 > 200 字符 |
  | `ERR_SYNTAX` | 非法字符、数字 malformed、括号不配对/位置错误、缺操作数、运算符结尾等 |
  | `ERR_NESTING` | 括号嵌套深度 > 16（解析时发现） |
  | `ERR_OVERFLOW` | 字面量 / 任何中间结果 / 最终结果的绝对值 > 10¹⁸ |
  | `ERR_DIV_ZERO` | 除零（按求值到达顺序报告） |

**路由规则**

每题给出 `id d t s`：`d`/`t` 分别为 direct / tool 路径是否正确（0 或 1，**仅供评分**，路由决策时不得使用），`s` 为工具需求分数（整数，0 ≤ s ≤ 10⁹）。预算为整数百分比 b（0–100）：最多调用 `k = floor(N × b / 100)` 次（必须用整数运算，四舍五入可能超预算，禁止）。选分数最高的 k 题，同分按输入顺序优先。

**输入格式**

```text
C
<expr>          （共 C 行，表达式为整行剩余内容，可能含空格、可能为空行）
R
N b             （第 1 个批次的题目数与预算）
id d t s        （共 N 行）
N b             （第 2 个批次……）
…               （共 R 个批次）
```

**输出格式**

- 每个 CALC 查询输出一行：十进制整数结果，或上表中的一个错误码；
- 每个 ROUTE 批次输出两行：
  - `CALL <id1> <id2> …`：被选中的题目 id，按**输入顺序**排列；若一题未选，输出 `CALL -`；
  - `RESULT <c>/<N> <acc>% <k>/<N> <rate>%`：c 为答对题数（被选题按 tool 结果、未选题按 direct 结果计），acc 与 rate 为百分比，保留两位小数（Python f-string 格式化）。

**样例输入**

```text
3
1+2*3
(1+2)*3
7/2
1
6 50
q1 1 1 10
q2 1 0 20
q3 0 1 95
q4 0 1 90
q5 0 0 30
q6 1 1 40
```

**样例输出**

```text
7
9
3
CALL q3 q4 q6
RESULT 5/6 83.33% 3/6 50.00%
```

样例说明：`floor(6×50/100) = 3`，分数最高的三题为 q3(95)、q4(90)、q6(40)；被选题按 tool 正误、未选题按 direct 正误对账，答对 q1、q3、q4、q6 及 direct 正确的 q2 共 5 题。

**数据范围与提示**

- CALC 查询数 C ≤ 50000；ROUTE 批次数 R ≤ 5，每批 N ≤ 100000；语言 Python 3，仅标准库；
- 评测为全文精确比较：注意每行格式、空格与末尾换行；
- 框架的 `main()` 已完成解析与对账，你只需实现 `calc(expr)` 与 `route(items, budget_percent)` 两个函数。

## 上传与打包说明

1. 在 OJ 后台新建题目（建议标题「选择性工具调用：安全计算器与预算路由」），语言限定 Python 3，粘贴上方题面；
2. 测试数据用「数据 (zip)」上传，**格式要求严格**（见 OJ 官方帮助页「如何创建数据包？」/ `/OnlineJudge/help/admin/data-format`）：**压缩包文件名必须是 `题号.zip`**（题号是数据库主键 id），且**包内顶层是以题号命名的文件夹**，文件放在其中：`题号.zip/题号/1.in`、…、`题号.zip/题号/config.json`（结构与 A+B 数据包 `1000.zip/1000/…` 一致）。`config.json` 缺失或路径不对会报"需要 json 文件"之类的错误。在本目录执行（把 `<ID>` 换成实际题号，**两处都要换**）：

   ```bash
   cd testcases && mkdir -p <ID> && cp *.in *.out config.json <ID>/ && zip -r ../<ID>.zip <ID> && rm -rf <ID>
   ```

   若使用「数据（GUI）」上传，则逐点上传 `.in`/`.out` 并按 `config.json` 手工建组：simple（1–4）20 分、complex（5–10）30 分、large（11–13）30 分、robust（14–16）20 分；所有测试点时限 2000 ms，内存均 256 MiB，无需 SPJ（`SPJ: 0`）；
3. 如需重新生成或调整测试点，运行 `python3 ta/include/gen_testcases.py include/testcases`（生成器内置独立的调度场求值器与 heapq 选择器，与递归下降的参考答案交叉验证），随后 `bash ta/include/verify_testcases.sh` 逐点做字节级 diff 与计时。

## 测试点一览

| 编号 | 分组 | 考查点 |
| --- | --- | --- |
| 1 | simple | 题面样例：优先级/括号/整数除法 + 六题 50% 预算路由（可手算） |
| 2 | simple | 一元负号与左结合：`-3*-4`、`-(2+3)`、`10-2-3`、`--3`、`2*-3` |
| 3 | simple | 向零取整除法：`-7/2=-3`、`7/-2=-3`、`-7/-2=3`（Python `//` 的陷阱） |
| 4 | simple | 预算两端：b=0 全 direct（`CALL -`），b=100 全 tool |
| 5 | complex | 空白字符无处不在（空格、制表符、行首尾） |
| 6 | complex | 语法错误大全 + 除零（含 `5/(3-3)`） |
| 7 | complex | 空表达式 / 纯空白表达式 → `ERR_EMPTY` |
| 8 | complex | 预算是 floor：N=3 b=50 只能调 1 次；N=7 b=99 只能调 6 次 |
| 9 | complex | 同分平局按输入顺序选择 |
| 10 | complex | 工具伤害：高分题 tool 错 direct 对，选中后准确率下降 |
| 11 | large | 5 万条四则运算查询 |
| 12 | large | 10 万题路由，预算 37% |
| 13 | large | 混合负载：2 万条计算 + 5 批各 2 万题路由 |
| 14 | robust | 嵌套 16 层合法 / 17 层 `ERR_NESTING`；长度 200 合法 / 201 `ERR_TOO_LONG` |
| 15 | robust | 溢出边界：字面量、中间结果、最终结果超过 10¹⁸ |
| 16 | robust | N=1 b=50 → floor(0.5)=0 一次都不能调；N=1 b=100 |

参考答案本机实测：全部 16 点通过，最慢测试点约 256 ms，远低于 2000 ms 时限。
