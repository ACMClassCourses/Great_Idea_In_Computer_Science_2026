# 基于 LSH 的 MNIST 近似最近邻检索：代码编写指南

## 1. 项目目标

本项目使用 MNIST 训练集建立近似最近邻索引，再依次查询测试集图片。对每张测试图片，程序在 LSH 找到的候选训练图片中计算精确距离，取最近图片的标签作为预测结果，最后输出数字识别准确率。

实现时优先保证以下三点：

1. 算法流程清楚，入门学生能够读懂和调试；
2. 确实利用 LSH 缩小候选集合，而不是每次遍历全部训练集；
3. 能够稳定读取当前 `test/data` 下的标准 MNIST IDX 文件并完成测试。

不需要配置文件、线程池、通用容器库、复杂日志系统或过度的输入校验。

## 2. 推荐的整体方案

建议使用 **随机超平面 LSH（Random Hyperplane LSH）**。

一张 MNIST 图片可看作 784 维向量。对每个随机超平面，计算图片向量与超平面向量的点积：

- 点积大于等于 0，得到哈希位 `1`；
- 点积小于 0，得到哈希位 `0`。

连续计算 `K` 个哈希位后，将这些位拼成一个 `K` 位整数，即该图片在一张哈希表中的桶号。建立 `L` 张彼此独立的哈希表，可以提高真正近邻至少在一张表中发生碰撞的概率。

查询流程如下：

```text
测试图片
   │
   ├─ 在 L 张表中分别计算桶号
   │
   ├─ 合并这些桶中的训练图片编号，并去重
   │
   ├─ 对候选图片计算精确平方欧氏距离
   │
   └─ 返回距离最小者的标签
```

随机超平面的每一维不必使用浮点高斯随机数。为了简化实现，可以让每个系数以相同概率取 `+1` 或 `-1`。这样哈希计算只需要整数加减法，也不需要保存或归一化浮点图片。

## 3. 建议的源文件结构

建议将代码控制在三个模块内：

```text
src/
├── main.c       程序入口、参数、计时和准确率统计
├── mnist.h      MNIST 数据结构和读取接口
├── mnist.c      IDX 文件读取与数据释放
├── lsh.h        LSH 数据结构和公开接口
└── lsh.c        建表、候选检索和最近邻查询
```

不建议继续拆分随机数、向量距离、动态数组等小模块。它们可以作为 `static` 辅助函数留在 `lsh.c` 中。

模块之间的依赖保持单向：

```text
main.c ──调用──> mnist.c
   │
   └───────────> lsh.c

lsh.c 只接收图片数组和数量，不负责打开 MNIST 文件。
```

## 4. 数据表示

### 4.1 MNIST 数据集

建议在 `mnist.h` 中定义一个简单的数据集结构，字段含义如下：

```c
typedef struct {
    int count;
    int rows;
    int cols;
    unsigned char *images;
    unsigned char *labels;
} MnistDataset;
```

所有图片连续保存在一块内存中。第 `i` 张图片的首地址为：

```text
images + i * rows * cols
```

MNIST 像素范围为 0～255，使用 `unsigned char` 足够。没有必要把全部训练集转换成 `float` 或 `double`，否则只会增加内存占用。

### 4.2 LSH 参数

建议先使用以下默认参数：

| 参数 | 建议值 | 含义 |
|---|---:|---|
| `DIM` | 784 | 图片向量维数 |
| `L` | 16 | 哈希表数量 |
| `K` | 12 | 每张表使用的哈希位数 |
| `BUCKET_COUNT` | `1 << K` | 每张表的桶数 |
| 随机种子 | 固定常数，如 42 | 使运行结果可复现 |

`K` 必须小于等于用于保存桶号的整数位数。本项目直接限制为不超过 20 即可，但默认值固定为 12 时不必编写复杂的通用校验。

参数的作用：

- 增大 `K`：桶更多、更小，查询更快，但可能漏掉近邻；
- 增大 `L`：候选更多、准确率通常更高，但内存和建表时间增加；
- 查询相邻桶：候选更多、准确率提高，但查询变慢。

### 4.3 哈希桶

由于哈希签名正好是 `0` 到 `(1 << K) - 1` 的整数，不需要实现通用哈希表。每张 LSH 表直接分配 `1 << K` 个桶，并用签名作为数组下标。

每个桶保存落入该桶的训练图片编号。桶可以使用最小动态数组结构：

```c
typedef struct {
    int *ids;
    int size;
    int capacity;
} Bucket;
```

容量不足时按两倍扩容。初始状态令 `ids = NULL`、`size = 0`、`capacity = 0`，第一次插入时分配一个较小容量，例如 4。

### 4.4 一张表与整个索引

一张表需要保存自己的 `K` 个随机超平面和全部桶：

```c
typedef struct {
    signed char *planes;
    Bucket *buckets;
} LshTable;
```

`planes` 按一维连续数组保存，长度为 `K * DIM`。每个值只取 `-1` 或 `+1`，因此 `signed char` 足够。

整个索引建议保存：

```c
typedef struct {
    int table_count;
    int bits_per_table;
    int dimension;
    int bucket_count;
    LshTable *tables;
    const unsigned char *train_images;
    const unsigned char *train_labels;
    int train_count;
} LshIndex;
```

图片和标签由 `MnistDataset` 拥有，`LshIndex` 只保存指针，不重复复制。释放资源时先释放 LSH 索引，再释放 MNIST 数据集。

## 5. MNIST IDX 文件读取

当前项目包含：

```text
test/data/train-images.idx3-ubyte
test/data/train-labels.idx1-ubyte
test/data/t10k-images.idx3-ubyte
test/data/t10k-labels.idx1-ubyte
```

IDX 文件头中的整数采用大端序，而常见 PC 使用小端序，因此需要编写一个读取 4 字节大端整数的辅助函数。

图片文件格式：

| 字段 | 长度 |
|---|---:|
| magic number，值为 2051 | 4 字节 |
| 图片数量 | 4 字节 |
| 行数 | 4 字节 |
| 列数 | 4 字节 |
| 像素数据 | `数量 × 行数 × 列数` 字节 |

标签文件格式：

| 字段 | 长度 |
|---|---:|
| magic number，值为 2049 | 4 字节 |
| 标签数量 | 4 字节 |
| 标签数据 | `数量` 字节 |

推荐读取步骤：

1. 分别打开图片文件和标签文件；
2. 读取两个文件头；
3. 只做必要检查：文件成功打开、magic number 正确、图片数量等于标签数量；
4. 为全部像素和标签各分配一块连续内存；
5. 使用一次 `fread` 读取全部像素，再使用一次 `fread` 读取全部标签；
6. 关闭文件并填写 `MnistDataset`。

发生失败时，释放本函数已经分配的内存并返回失败即可。无需逐像素检查，也无需验证每个标签是否都在 0～9 内。

建议接口：

```c
int mnist_load(const char *image_path,
               const char *label_path,
               MnistDataset *dataset);

void mnist_free(MnistDataset *dataset);
```

## 6. 哈希函数的实现细节

### 6.1 生成随机超平面

对每张表生成 `K × DIM` 个随机符号。可直接使用标准库 `rand()`：

```text
rand() 的最低位为 0 -> -1
rand() 的最低位为 1 -> +1
```

在程序开始建表前只调用一次 `srand(固定种子)`，不要为每张表重复设置种子，否则不同表可能生成完全相同的超平面。

### 6.2 计算一个哈希签名

对某张表中的第 `b` 个超平面，计算：

```text
dot = Σ image[d] × plane[b][d]
```

因为像素最大为 255，784 项之和的绝对值小于 20 万，使用 `int` 足够。

若 `dot >= 0`，将签名的第 `b` 位设为 1：

```text
signature |= 1u << b
```

计算完 `K` 个点积后，`signature` 就是桶数组下标。

建议把此过程封装成 `lsh_signature`，供建表和查询共同调用，避免两处位运算不一致。

### 6.3 不需要图片归一化

随机超平面哈希只关心点积的正负，向量整体乘以正数不会改变签名，因此本项目可以直接使用原始 0～255 像素。最终候选排序仍使用平方欧氏距离。

## 7. 建立 LSH 索引

建议公开接口：

```c
int lsh_build(LshIndex *index,
              const unsigned char *train_images,
              const unsigned char *train_labels,
              int train_count,
              int dimension,
              int table_count,
              int bits_per_table);

void lsh_free(LshIndex *index);
```

建表过程：

1. 初始化 `LshIndex` 的参数；
2. 分配 `L` 个 `LshTable`；
3. 为每张表分配随机超平面数组和桶数组；
4. 生成该表的所有随机超平面；
5. 依次遍历 60000 张训练图片：
   - 计算图片在当前表中的签名；
   - 将训练图片编号追加到对应桶；
6. 所有表完成后返回成功。

可以按“先完成一张表，再处理下一张表”的顺序编写。这样代码结构简单，访问同一组超平面和桶时也较集中。

若中途分配失败，直接调用能够处理部分初始化状态的 `lsh_free`。为此，所有结构在开始时应清零，释放函数对空指针调用 `free` 即可。

## 8. 查询候选集合

### 8.1 基本查询

对一张测试图片：

1. 在每张表中计算签名；
2. 访问对应桶；
3. 将桶内训练图片编号加入候选数组；
4. 跳过已经加入过的编号。

必须去重。若同一训练图片在多张表中与查询图片碰撞，重复计算距离虽然不会产生新信息，而且在以后扩展到多数投票时还会错误地增加它的权重。

### 8.2 简单高效的去重方式

建议在查询器中准备一个长度为 `train_count` 的 `int` 数组 `seen`，初始全部为 0，并维护递增的 `query_mark`：

```text
开始第 q 次查询：query_mark 加 1

遇到训练编号 id：
    如果 seen[id] != query_mark：
        seen[id] = query_mark
        加入候选数组
```

这样不必为每张测试图片都清空 60000 个元素，也不需要实现集合或通用哈希表。查询 MNIST 的 10000 张测试图片时，`int` 不会溢出，因此无需处理标记回绕。

候选数组最大只需分配 `train_count` 个 `int`，每次查询复用同一块内存。

### 8.3 候选过少时查询相邻桶

只查询完全相同的桶时，少数图片可能没有候选或候选太少。建议采用一层简单的多探测策略：

1. 先收集所有表中与查询签名完全相同的桶；
2. 如果候选数少于一个阈值，例如 20，再查询每张表中与原签名只相差 1 位的 `K` 个桶；
3. 达到阈值后仍可直接停止扩展，或者为保持代码最直观而完成这一层全部桶的收集。

相差第 `b` 位的相邻签名为：

```text
neighbor_signature = signature ^ (1u << b)
```

不建议一开始实现汉明距离 2 或更复杂的优先队列式多探测。默认 `L = 16、K = 12` 时，同桶加一位相邻桶通常已经能提供足够候选。

如果全部候选仍为空，可将“没有找到近邻”作为查询失败返回。正常参数下这种情况几乎不会发生，不必回退到扫描整个训练集，否则会掩盖 LSH 参数设置问题。

## 9. 精确距离与分类

对候选集合中的每张训练图片计算平方欧氏距离：

```text
distance = Σ (query[d] - train[d])²
```

不需要调用 `sqrt`。平方根是单调函数，距离平方最小的图片也一定是欧氏距离最小的图片。

单维差值范围是 -255～255，总距离平方最大约为 5100 万，32 位有符号 `int` 足够。计算时先将两个 `unsigned char` 转为 `int` 再相减，避免无符号减法回绕。

本项目推荐使用 **1-NN**：

```text
预测标签 = 候选集合中距离最小图片的训练标签
```

1-NN 已经能够完整展示“LSH 候选检索 + 精确重排 + 数字分类”的流程。暂时不必实现 `k` 个最近邻、堆和多数投票。

建议查询接口：

```c
int lsh_predict(const LshIndex *index,
                const unsigned char *query_image,
                int *seen,
                int query_mark,
                int *candidates,
                int *candidate_count,
                unsigned char *predicted_label);
```

也可以把 `seen`、候选数组和标记封装到单独的 `LshQueryWorkspace` 中；但对本项目而言，直接由 `main.c` 分配并传入更容易理解。

当两个候选距离相同时，保留先遇到的候选即可。无需额外设计随机或标签优先规则。

## 10. 主程序职责

`main.c` 建议只完成以下工作：

1. 确定四个 IDX 文件路径；
2. 加载训练集和测试集；
3. 检查训练集与测试集的图片尺寸相同；
4. 使用固定随机种子建立 LSH 索引；
5. 分配并初始化查询工作区；
6. 对测试集逐张调用 `lsh_predict`；
7. 比较预测标签与真实标签并统计正确数量；
8. 输出准确率、平均候选数，以及可选的建表和查询耗时；
9. 按与创建相反的顺序释放资源。

推荐的最简命令行形式为：

```text
program [data_directory]
```

若未提供目录，默认使用 `test/data`。`L`、`K`、候选阈值和随机种子可以先定义成 `main.c` 顶部的常量，不必为每个参数编写命令行解析。

推荐输出：

```text
Training images: 60000
Test images: 10000
LSH tables: 16, bits per table: 12
Average candidates: ...
Correct: ... / 10000
Accuracy: ...%
```

输出不必逐张打印预测结果，否则会使正常运行的输出过长。调试时可以临时只处理前几十张并打印详情，完成后再恢复全量测试。

## 11. 内存释放顺序

建议按以下顺序释放：

1. 查询使用的 `seen` 和 `candidates`；
2. 对每张 LSH 表：
   - 释放每个桶的 `ids`；
   - 释放桶数组；
   - 释放随机超平面数组；
3. 释放 LSH 表数组；
4. 释放测试集图片和标签；
5. 释放训练集图片和标签。

`mnist_free` 和 `lsh_free` 在完成释放后应将结构清零。这样失败路径也可以安全复用正常的清理代码。

## 12. 推荐的实现顺序

不要一次写完整个项目。按下面顺序实现，每一步都能独立验证：

### 第一步：读取 MNIST

完成 `mnist_load` 和 `mnist_free`，在主程序中输出：

- 训练集数量应为 60000；
- 测试集数量应为 10000；
- 行列应为 28 × 28；
- 前几个标签应在 0～9 范围内。

### 第二步：完成单个哈希签名

固定随机种子，对同一张图片重复计算签名，结果必须一致。不同训练图片通常会得到不同签名。

### 第三步：建立一张哈希表

先令 `L = 1`，完成桶的分配、插入和释放。统计所有桶的 `size` 之和，应等于训练图片数量。

### 第四步：建立完整索引

恢复 `L = 16`，确认每张表中桶元素总数都等于 60000。

### 第五步：完成候选检索和 1-NN

先查询训练集中的图片本身。它在每张表中的签名必然与自身相同，候选中应包含自身，最近距离应为 0，预测标签应正确。

### 第六步：评估测试集

先运行前 100 张测试图片，确认候选数和预测结果合理，再运行全部 10000 张并统计准确率。

## 13. 调参与结果判断

最值得观察的两个指标是准确率和平均候选数：

- 准确率低、平均候选数也很少：增加 `L`，减小 `K`，或启用一位相邻桶；
- 准确率较高、平均候选数接近 60000：索引筛选能力太弱，应增大 `K`；
- 查询经常没有候选：减小 `K` 或增加 `L`；
- 运行结果每次变化：检查是否固定了随机种子，以及是否存在未初始化内存。

推荐调参顺序：

1. 固定 `K = 12`，将 `L` 从 8 调到 16；
2. 启用候选不足时的一位相邻桶查询；
3. 再尝试 `K = 10、12、14`，比较准确率和平均候选数；
4. 选择在本机运行时间合理且准确率较高的一组参数。

MNIST 原始像素上的精确 1-NN 通常能达到较高准确率；LSH 会用一定的准确率损失换取更小的候选集合。具体结果依赖随机超平面和参数，因此不应在代码中写死某个“必然达到”的准确率。若准确率明显低于 90%，首先检查候选是否过少以及距离计算是否正确。

## 14. 必要检查与不必要设计

### 应保留的检查

- 文件是否成功打开；
- IDX magic number 是否正确；
- 图片数和标签数是否一致；
- 内存分配是否成功；
- 训练集和测试集维数是否一致；
- 查询是否得到候选。

### 本项目不需要的内容

- 自定义通用哈希表；
- 通用泛型动态数组；
- JSON、YAML 或配置文件；
- 多线程和线程同步；
- SIMD、GPU 或手写汇编；
- 图片格式转换和图形界面；
- 对每个像素、标签和命令行参数做重复校验；
- 为极端大数据量设计磁盘索引；
- 复杂的类层次或回调函数框架。

如果某项设计不能直接帮助“读入 MNIST、建立 LSH、寻找候选、完成分类、计算准确率”这条主线，就先不要加入。

## 15. 最终检查清单

完成代码后，确认：

- [ ] 能正确读取四个 MNIST IDX 文件；
- [ ] 图片以连续 `unsigned char` 数组保存；
- [ ] 每张 LSH 表拥有独立随机超平面；
- [ ] 建表和查询调用同一个签名函数；
- [ ] 桶号始终在 `0` 到 `(1 << K) - 1` 范围内；
- [ ] 每张表中全部桶的元素总数等于训练集大小；
- [ ] 候选图片编号已经去重；
- [ ] 候选较少时会查询一位相邻桶；
- [ ] 距离使用平方欧氏距离，没有不必要的 `sqrt`；
- [ ] 使用候选中最近训练图片的标签进行 1-NN 分类；
- [ ] 能输出正确数、总数、准确率和平均候选数；
