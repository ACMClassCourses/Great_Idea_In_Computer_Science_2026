## A1：简单状态消除程序

将 Basic 中手工完成的转换过程写成程序：输入一台只有少量状态的有限状态机，输出描述同一语言的正则表达式。

实现范围可以限制为：

- 2 至 4 个状态；
- 单字符输入符号；
- 支持正则表达式的连接、`|`、`*` 和括号；
- 能按明确的顺序消除中间状态。

输入输出格式可自行设计，需要在运行说明中给出状态、初始状态、接受状态和转移的表示方式。说明空串与空语言在程序内部的表示方法；如有其他限制，也应写清楚。

实现时考虑如何进入被消除状态、在其中循环、再离开它，以及如何保留原有路径。验证至少包含连续路径、循环和多条可选路径的案例，不要求生成最短正则表达式，也不要求完成完整的在线评测题。

验证生成结果时，可枚举一定长度以内的字符串，比较状态机模拟与正则表达式完整匹配的结果。报告枚举范围；有限枚举用于检查实现，同时需要解释转换规则为什么保持语言不变。

## A2：其他模数的余数状态机

将模三问题推广到判断二进制数能否被其他正整数 `m` 整除。

需要说明：

- 状态如何对应余数，初始状态与接受状态是什么；
- 为什么转移公式可以写成 `new_r = (2 * r + b) % m`；
- 与模三机相比，状态数和转移表怎样变化。

给出至少一个其他模数的完整状态表，并用已完成的 Basic 模拟器或自行编写的程序验证。可以进一步尝试把它转换成正则表达式。

## A3：比较不同状态消除顺序

选择同一个状态机，至少使用两种不同的状态消除顺序，记录中间步骤与最终表达式。

说明表达式的形式、长度或括号层数怎样变化，并解释为什么它们仍描述相同的语言。可以手工分析，也可以在 A1 程序中切换消除顺序进行实验。

## A4：简化生成的正则表达式

研究路径合并、重复选择消除、公共前缀或后缀提取等简化方法。

给出采用的规则、简化前后的表达式和保持等价的理由，并验证结果。无需寻找或证明全局最短表达式。
