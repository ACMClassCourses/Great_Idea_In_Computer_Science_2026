## A 问题是什么

1852 年，一个画地图的学生发现：给地图上色，使得相邻区域颜色不同，似乎四种颜色永远够用。这个"四色猜想"折腾了人类一百多年。但你有没有先问过另一个问题——**三种颜色，够不够？**

这个问题没法靠定理回答。判定"一张地图能否三染色"是计算机科学中最著名的难题类别——**NP 完全问题**——的一员：答案容易验证（给我染色方案，我一眼看出对错），却没有人知道怎么快速求解（已知的通用方法本质上都要枚举指数级的可能性）。

图染色绝不是只存在于数学题里的游戏，它藏在许多你每天接触的系统中：

- **编译器给变量分配寄存器**：两个变量若在同一时刻都"活着"，就不能共用寄存器——把变量画成顶点、冲突画成边，寄存器分配就是图着色，颜色就是寄存器编号。现代编译器（GCC、LLVM）每天都在解这个问题；
- **教务系统排考试**：任意两门有学生同时选修的考试不能安排在同一时段——课程是顶点，时段是颜色；
- **无线电频点分配**：相邻基站不能用同一频率，否则互相干扰。

这些应用有一个共同的坏消息：它们的核心是 NP 完全的，**不存在已知的通用快速算法**。那现实世界怎么办？这正是本项目要带你体验的事情——不是"学会一个算法"，而是**模拟一次完整的科研探索**：面对一个公认"难"的问题，先用最朴素的方法亲身感受它有多难，再像研究者一样，用启发式与剪枝把"难"的边界一点点往外推，并用对照实验证明自己推了多远。

最终你将交付：一个三染色判定器 + 三组算法的性能对比实验 + 一次课堂展示。

### 三个核心思想

1. **抽象与归约**。地图染色不是地理问题：把每个区域缩成一个点、相邻关系连一条边，地图就变成了**图**——拓扑、形状、面积全部扔掉，只留下本质结构。"把问题翻译成已知问题"是计算机科学最重要的思维方式之一。
2. **P 与 NP 之间的悬崖**。二染色（二分图判定）有线性时间算法；三染色却是 NP 完全的。**只多一种颜色，问题从"瞬间可解"掉进"无人会解"**。更惊人的是：即使限制在平面图上，三染色依然是 NP 完全的（Garey–Johnson–Stockmeyer, 1976）——而四色定理保证了平面图四染色永远有解，甚至有 O(n²) 算法。（你可以查阅<https://github.com/stefanutti/maps-coloring-python>作简要理解）2、3、4 三种颜色，恰好踩在难易分界线的三个格点上。
3. **搜索的艺术**。当指数爆炸不可避免，工程上的回答是：少搜。MRV 启发式（每次给"剩余选择最少"的顶点上色）和前向检查（染一个顶点，立刻收缩其邻居的可用颜色）都是 CSP（约束满足问题）的经典技术，也是今天 SAT 求解器、数独求解器的祖先。

| 基础要求 | 说明 |

| 返回 | 长度为 n 的列表（元素 ∈ {0, 1}），或不可染时返回 `None` |

```bash
python src/check.py                                        # 任务一应当通过
python src/main.py solve --data data/grid_4x4.txt          # 网格图（二分图）
python src/main.py solve --data data/triangle.txt          # 三角形：二染色失败
```

**思考**：

- 亲手掐表或数操作次数，说明二染色为什么是**线性**的——每条边、每个顶点被"碰"了几次？
- 二染色为什么**不需要回溯**？染了第一个顶点后，其余顶点的颜色还有"选择"吗？想明白这一点，你就抓住了三染色变难的真正根源。
- 网格图为什么一定是二分图？试给出一个小证明（提示：看行号+列号的奇偶性）。

记住这个"线性时间"的感觉吗？很遗憾，下个任务你会失去它。

### 任务二 朴素回溯三染色

在 `src/solver.py` 中完成 `three_color_backtrack(n, adj, stats)`：按固定顶点顺序（0, 1, 2, …）逐个染色，每个顶点依次尝试颜色 0、1、2，与已染色邻居冲突就换色，三条路都走不通就回溯。每进入一次递归，`stats["nodes"] += 1`。

```bash
python src/main.py solve --data data/triangle.txt          # 可三染色
python src/main.py solve --data data/k4.txt                # K4：不可三染色
python src/main.py solve --data data/mycielski4.txt        # 没有三角形，却仍需 4 色（想想为什么神奇）
```

**指数爆炸实验（你的第一次对照实验）**：用 `python src/main.py gen --n 20 --m 32 --seed 1` 生成随机图，逐渐增大 n，记录搜索节点数 `stats["nodes"]`：

```bash
python src/main.py bench --sizes 10 12 14 16 18 20
```

**思考**：

- 把"n vs 搜索节点数"画成图（或列表），估计增长率：节点数大致是 `c^n` 的形式吗？c 大约是多少？
- 搜索树的理论最坏规模是 3ⁿ，你实测的远小于它——**是什么在替你"免费"剪掉分支**？
- **注意**：随机图有个"相变"现象——平均度数约 4.7 附近的实例最难，太稀疏或太稠密反而容易。如果你观察到了"先变难后变易"，如实记录——这是进阶部分"相变实验"的入口。
- Mycielski 图（`mycielski4.txt`）一个三角形都没有，却仍然不能三染色。这说明"难"一定有显而易见的局部理由吗？这对"验证容易、求解难"的 NP 完全性意味着什么？

### 任务三 MRV 启发式与前向检查

在 `src/solver.py` 中完成 `three_color_mrv(n, adj, stats, forward_check)`：

- **MRV（Most Constrained Variable，最受约束者优先）**：每一步不按固定顺序，而是选择**当前剩余可用颜色最少**的未染色顶点先染（平局时取度数较大者）。直觉：最容易卡死的先安排，早死早超生，避免把灾难留到最后。
- **前向检查（Forward Checking）**：染完一个顶点，立刻把它所有未染色邻居的可用颜色集合删掉该颜色；若某邻居的可用色变空，立即回溯——不用等到亲自染到它才发现死路。

```bash
python src/main.py solve --data data/rand.txt --mrv --fc
python src/main.py bench --sizes 10 14 18 22 26 30 --skip-naive
```

**性能对比实验**：在同一批实例上分别跑 朴素 / MRV / MRV+前向检查 三组，对比搜索节点数与耗时，画对比曲线。这是标准的**消融实验**（ablation study）：逐个加入优化，分离每个优化的贡献——机器学习论文里最经典的实验范式，你在这里就能体验。

**思考**：

- MRV 为什么有效？前向检查为什么有效？它们的代价是什么（每步多做了什么工作）？
- MRV 只改变**染色顺序**，为什么不会把"可染的图"误判成"不可染"？（提示：每个顶点最终是否仍尝试了所有颜色？）这个性质叫**完备性**，是所有搜索算法的生命线。
- 前向检查为什么只是"提前发现死路"而不改变答案？它与"改变搜索空间本身"有什么区别？

### OJ 提交（Basic 验收）

任务二（朴素回溯三染色）在课程 OJ（ACMOJ）上有对应题目，**Basic 部分的代码验收以 OJ 数据点为准**。请从 OJ 题目页面（或本仓库 `include/src/`）下载单文件框架 `three_color.py`，补全其中的 `three_color(n, adj)` 后提交。OJ 版本与 `src/` 框架的输入输出不同：从**标准输入**读图、向**标准输出**打印结果，且搜索规则完全钉死以保证输出唯一：

**输入格式**：第一行 `n m`（顶点数、边数，顶点编号 `0..n-1`，1 ≤ n ≤ 500，无重边）；随后 m 行每行 `u v`。若某条边 u == v（自环），直接输出 `UNSAT` 与 `NODES 0`（该判断已由框架的 main 完成）。

**输出格式**：

- 顶点染色顺序固定为 `0, 1, …, n-1`；每个顶点按颜色 `0, 1, 2` 顺序尝试；只与**已染色**邻居判冲突；找到第一个完整方案立即输出并结束；
- 可三染色时输出三行：`SAT`、一行 n 个空格分隔的颜色、`NODES x`；不可染色输出两行：`UNSAT`、`NODES x`；
- `NODES` = 进入递归函数的总次数：`dfs(v)` 表示"给顶点 v 染色"，`dfs(0)` 的首次调用计入，`v == n` 的成功终止调用也计入。

**样例输入**（三角形）：

```text
3 3
0 1
1 2
2 0
```

**样例输出**：

```text
SAT
0 1 2
NODES 4
```

评测为全文精确比较（注意大小写、空格与末尾换行），所有测试点时限 2000 ms、内存 256 MiB。数据点分 simple / complex / large / robust 四组：既有可手算的小例子，也有 n=500 的偶环、1600 条边的完全二分图和随机图——跑过大点再想想：朴素回溯的效率到底由什么决定？

### C1 相变：难问题的"山峰"在哪里？

固定 n（如 40），让平均度数从 2 扫到 6，每个度数生成多个随机实例取中位数，画出"难度（节点数）随度数变化"的曲线。你应当看到一座明显的"山峰"——这就是著名的 **easy-hard-easy 相变**。

- **思考**：山峰为什么恰好在"可染与不可染各占一半"的地方？
- **推荐阅读**：Cheeseman, Kanefsky & Taylor, *Where the Really Hard Problems Are*（IJCAI 1991）——"最难的实例在哪里"这个问题的开山之作，网上可找到 PDF。

### C2 更多 CSP 技术：还能再砍几个数量级吗？

实现以下任意组合，各自测量能再降多少节点：

- **LCV（Least Constraining Value）**：选颜色时优先"对邻居限制最小"的；
- **AC-3 弧一致性**：比前向检查更强的约束传播；
- **连通分量分解**：不连通的图拆开分别求解（平凡但有效）。

- **思考**：MRV 管"选哪个变量"，LCV 管"选哪个值"，AC-3 管"传播多远"——三者正交，可以叠加。它们的组合有没有理论极限？
- **推荐阅读**：Russell & Norvig《人工智能：一种现代方法》第 6 章后半部分。

### C3 把三染色"翻译"成 SAT，并亲手写一个迷你 SAT 求解器

三染色是 NP 完全的，意味着它可以**归约**为任何其他 NP 完全问题。试试：把"图能否三染色"编码成一组布尔公式（每个顶点三个变量表示颜色，约束"每个顶点恰好一色"+"相邻顶点不同色"），然后实现一个最简单的 **DPLL 求解器**（回溯 + 单元传播）来求解。

- **思考**：这不需要任何第三方库，DPLL 的核心只有几十行。完成后对比：你的通用 DPLL 和任务三的专用求解器，谁更快？为什么工业界反而押注通用 SAT 求解器？
- **推荐阅读**：任何一篇 DPLL 算法教程；学有余力可读 MiniSat 论文（Eén & Sörensson 2003），再看看 [SAT Competition 官网](http://www.satcompetition.org/)——你写的回溯搜索的"曾孙们"每年在那里比武。

### C4 当搜索遇上学习：机器能学会"怎么搜"吗？

你在任务三里**手工设计**了启发式（MRV）。一个大胆的问题：能不能让机器从大量已解实例中**学出**选顶点的策略？哪怕不用神经网络——只用你在任务二、三里收集的（实例特征 → 最优选择）数据，训练一个最简单的分类器来替代 MRV，效果会怎样？

- **引导**：这是"学习增强搜索"（learning to search）的最小原型，也是当前 AI 研究的热门方向。完全开放：特征怎么设计、数据怎么收集、"学得好"怎么衡量，都由你定义。
- **阅读**：Selsam et al., *Learning a SAT Solver from Single-Bit Supervision*（NeuroSAT，ICLR 2019，arXiv:1802.03685）——用图神经网络学解 SAT 的代表作，读懂大意即可。

## F 问题的来龙去脉与发展过程

**从地图到定理（1852–1976）**。四色问题由 Guthrie 在 1852 年提出，期间"证明"与"反例"轮番登场。1976 年 Appel 和 Haken 借助计算机验证了 1936 种可约构形，宣布四色定理成立——这是**第一个重要的计算机辅助证明**，引发了"机器证明算不算证明"的持久争论（这本身就是一个值得在课堂上讨论的"伟大思想"）。

**计算的极限（1971–1972）**。就在四色定理被证出的同一十年，计算机科学界正在建立另一座大厦：Cook 和 Levin 证明了 SAT 的 NP 完全性（1971），Karp 随即列出 21 个 NP 完全问题（1972）——**图三染色正是其中之一**。从此人们知道：这一类问题彼此"等价"，解决一个就等于解决全部；而它们全都可能不存在多项式算法。P vs NP 至今未解，悬赏百万美元。

**平面图的特殊性（1976）**。Garey、Johnson 和 Stockmeyer 证明了：**即使只考虑平面图，三染色仍是 NP 完全的**。另一边，四色定理 + Robertson 等人的 O(n²) 算法让"平面图四染色"落在 P 里。所以本项目用三染色而不是四染色——四色是"永远有解"的定理问题，三色才是搜索问题的真正战场。

**求解器的后代（今天）**。你在任务三实现的 MRV 与前向检查，是 CSP（约束满足）的经典技术；沿着这条路走下去是冲突驱动学习（CDCL）、watched literals，最终长成今天的工业级 SAT 求解器——它们在芯片验证、软件测试里每秒处理百万级约束。下次听说"某芯片通过了形式化验证"，背后就是你本周写的回溯搜索的曾孙。进阶部分 C3 会带你亲眼看看这条血脉。
