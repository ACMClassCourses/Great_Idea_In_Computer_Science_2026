# theory-2：停机问题

## A 问题是什么

能否写一个万能程序，输入任意程序及其输入数据，就总能在有限时间内判断它会不会结束？如果可以，编译器似乎就能事先找出所有死循环；如果不可以，这个限制究竟来自机器太慢，还是来自计算本身？停机问题揭示的是后一种边界：不存在对所有程序都正确、且总会结束的通用判定器。

本项目分 Basic 与 Advance 两个阶段。Basic 只需完成第 1 周内容：准确陈述停机问题，理解模拟、超时与判定的差别，完成对角线反证；Advance 完成其余内容：图灵机、可识别性、归约、Rice 定理与程序分析的边界，并完成一个有限范围的分析实验。

| 阶段 | 工作量安排 | 完成后的能力 |
| --- | --- | --- |
| Basic | 一周内约 10–20 小时 | 能复述停机问题，解释反证中的两种情况，说明超时为什么不能证明不停机 |
| Advance | 完成 Basic 后，再用六周推进（总计七周）；建议难度系数 0.9，以 project1 的 1.0 为基准 | 能构造简单归约，区分可判定与可识别，分析程序验证工具的能力边界 |

### Basic：停机、模拟与对角线法

Basic 的核心概念包含：程序编码、判定器、自指、反证法、对角线法。完成 Basic 时，须按 **Q1–Q3** 提交简短回答。

| 编号 | 需要回答的问题 |
| --- | --- |
| Q1 | 一个通用停机判定器需要满足哪些条件？ |
| Q2 | 直接运行程序或设定超时，为什么不能解决停机问题？ |
| Q3 | 假设判定器存在，如何构造一个与预测相反的程序？ |

**关键区分：**
- 不可判定不同于 NP-hard：前者没有符合要求的通用算法，后者讨论可计算问题的资源难度。
- 停机问题不可判定，不表示任何具体程序的终止性都无法证明。
- 证明讨论的是具有无界存储能力的理想化计算模型；固定有限状态系统可通过状态遍历分析。
- 量子计算可以改变某些问题的效率，但标准量子计算模型不能解决一般停机问题。

#### 1 学习目标

准确陈述停机问题，理解模拟与超时的差别，掌握对角线反证的基本结构。Basic 不要求另外提交书面问答，但须在提交材料中简要回答 Q1–Q3。

#### 2 本周用到的概念

本节介绍停机问题相关概念。不必构造完整的图灵机，只需理解反证的核心思路。

| 编号 | 概念 | 要点 | Basic 要不要 |
| --- | --- | --- | --- |
| C1 | 程序编码 | 任意程序可以编码为有限字符串 | **必看** |
| C2 | 判定器 | 接受程序编码和输入，输停机/不停机 | **必看** |
| C3 | 自指 | 程序可以得到自己的编码 | **必看** |
| C4 | 反证法 | 假设万能判定器存在，构造矛盾 | **必看** |
| C5 | 对角线法 | 通过自身编码对判定器进行对角线化 | **必看** |

#### 2 对角线反证骨架

假设 `H(code, input)` 总会结束，并正确判断程序是否停机。程序能够作为有限字符串编码，因此程序编码也可以作为输入。

```text
D(code):
    if H(code, code) == HALTS:
        loop forever
    else:
        return
```

令 `d` 为 `D` 的编码。若 `H(d, d)` 预测停机，`D(d)` 就不停；若预测不停，`D(d)` 就停。因此万能判定器不可能存在。这里的 `H` 只是反证中的假设，不是要求学生实现的函数。

#### 3 Basic 提交与验收

提交 Q1–Q3 的简短回答、对角线反证的证明笔记，以及假设、构造、自身输入与矛盾的明确描述。能够复述停机问题，解释反证中的两种情况，说明超时为什么不能证明不停机。

### Advance：可识别性、归约与程序分析

Advance 在 Basic 基础上讨论不可判定性如何传播，以及实际工具如何通过限制问题范围获得可用结果。

建议完成以下任务：

1. 用状态、纸带、读写头与转移规则解释图灵机；手工模拟一个二进制加一程序。
2. 说明停机集合为什么可识别，而不存在总能结束的判定器；解释“停机”与“接受”不是同一概念。
3. 证明停机集合的补集不可识别：如果一个集合及其补集均可识别，就可交替模拟两个识别器得到判定器。
4. 把停机问题归约到“程序是否最终输出标记 42”：构造先模拟原程序、待其停机后才输出标记的新程序，模拟期间屏蔽原程序输出。
5. 阅读 Rice 定理，给出两个非平凡语义性质与一个语法性质，说明定理的适用范围。
6. 实现有步数上限的小语言解释器，或有限状态程序分析器，记录 `HALTS`、`PROVED_LOOP`、`UNKNOWN` 三类结果。
7. 完成研究报告，围绕“限制输入、允许未知、接受近似”解释实际程序分析的取舍。

### 三类问题与方法

| 对象 | 是否有通用判定方法 | 可用方法 | 需要说明的限制 |
| --- | --- | --- | --- |
| 固定程序是否在给定步数内结束 | 可判定 | 最多模拟规定步数 | 未在期限内结束不等于永不结束 |
| 完整配置空间有限的确定性系统 | 可判定 | 遍历配置，检测停机或重复 | 配置需包含所有影响未来执行的信息 |
| 一般程序是否最终停机 | 不可判定，但可识别 | 模拟能确认正例 | 非停机输入可能让模拟一直运行 |
| 程序文本是否包含某个词 | 可判定的语法问题 | 扫描文本或语法树 | 不等同于程序实际执行到该语句 |
| 所计算函数的非平凡语义性质 | 一般不可判定 | Rice 定理分析 | 定理针对程序计算的部分函数性质 |

### 归约需要证明什么

若要证明问题 \(B\) 不可判定，应从已知不可判定的问题 \(A\) 出发，给出可计算变换 \(f\)，使 \(x\in A\) 当且仅当 \(f(x)\in B\)。这表示“如果能判定 B，就能判定 A”。归约方向写反，不能得到需要的结论。

归约构造程序时，不必先判断原程序是否停机；只需生成一个包含模拟逻辑的新程序。提交的证明应明确展示构造算法、两个方向的等价关系，以及假想判定器如何导出矛盾。

## 附录：问题的来龙去脉与发展过程

**从机械计算到形式模型。**  
“能否把推理交给一套机械规则”促使数学家精确定义算法。Church 的 λ 演算与 Turing 的机器模型从不同角度刻画有效计算，其等价性支持了丘奇–图灵论题。

**从万能机器到不能计算的问题。**  
程序可以编码为数据，通用机器因此能模拟其他程序。同一种能力也允许把程序放到自己的输入位置，构成对角线论证。计算能力的统一描述与计算边界来自同一个思想。

**从一个反例到一整类不可判定问题。**  
归约让我们把停机问题的困难传递给程序行为问题。Rice 定理进一步概括了部分可计算函数的非平凡语义性质所面临的限制，避免对每个性质重新发明证明。

**从理论边界到实用工具。**  
编译器、模型检查器和程序验证器仍然有价值：它们可以处理受限语言、有限模型或带证明的程序，也可以诚实返回未知。项目最终要理解的，是为什么一个工具应明确说明它对哪些输入、以什么意义给出保证。
