# 三染色项目代码编写指南

本文档是 `README.md` 的配套实现指南：先读 README 了解"做什么"，再读本文档了解"怎么写"。所有代码只需 Python 标准库。

## 1. 项目目标与原则

完成三个层层递进的求解器：

1. 二染色判定（线性时间，热身）；
2. 朴素回溯三染色（见证指数爆炸）；
3. MRV 启发式 + 前向检查（压缩搜索空间）。

实现原则：

- 简单、清楚、可调试优先，每个函数只做一件事；
- 图一律用**邻接表**（`list[set[int]]`），不自己造图类；
- 所有搜索函数都必须如实维护 `stats["nodes"]`——性能实验全靠它；
- 暂不考虑位运算优化、并行、启发式的花哨变体（那是进阶部分的事）。

## 2. 推荐架构

```text
src/
├── check.py    （完整提供）自测：正确性 + 性能对比断言
├── main.py     （完整提供）命令行入口：solve / gen / bench
├── graph.py    （完整提供）图文件读写、随机图与网格图生成、染色合法性验证
└── solver.py   （任务一~三）三个求解函数
```

依赖关系：`main.py`、`check.py` 都 import `graph.py` 和 `solver.py`；后两个文件互不依赖。

## 3. 数据表示

### 3.1 图

```python
n = 5
adj = [set() for _ in range(n)]   # adj[v] 是顶点 v 的邻居集合
```

顶点编号 `0..n-1`。无向图：边 `(u, v)` 意味着 `v in adj[u]` 且 `u in adj[v]`（`load_graph` 已保证双向写入）。

### 3.2 染色方案

一个长度为 `n` 的列表：`coloring[v] ∈ {0, 1, 2}` 表示顶点 v 的颜色。不可染色时返回 `None`——**不要**返回一个非法方案来冒充。

### 3.3 图文件格式

```text
# 注释行
5 4        ← n 个顶点，m 条边
0 1
1 2
2 3
3 4
```

`graph.py` 的 `load_graph` / `save_graph` 已经处理好读写，直接用。

### 3.4 搜索统计

每个求解函数接收一个 `stats: dict`，**每进入一次递归就 `stats["nodes"] += 1`**。这是性能实验的唯一度量——节点数与机器无关，比秒数更公平（耗时也记录，但只作参考）。

## 4. 函数契约

### `two_color(n, adj) -> list[int] | None`（任务一）

- BFS/DFS：未染色的顶点染 0，其邻居染 1，交替推进；发现同色的边即返回 `None`。
- 图可能不连通：外层要遍历所有尚未访问的顶点。
- 参考规模：约 20 行。

### `three_color_backtrack(n, adj, stats) -> list[int] | None`（任务二）

朴素回溯，没有任何启发式：

```text
def dfs(v):                       # 准备给顶点 v 染色
    stats["nodes"] += 1
    若 v == n：全部染完，返回成功
    对每个颜色 c ∈ {0, 1, 2}：
        若 c 与 v 的某个已染色邻居冲突：跳过
        coloring[v] = c
        若 dfs(v + 1) 成功：返回成功
        coloring[v] = 未染色      # 撤销！
    返回失败
```

要点：

- 顶点顺序固定为 `0, 1, …, n-1`（"朴素"就朴素在这里）；
- 冲突检查只看**已染色**邻居（未染色的邻居还没颜色，谈不上冲突）；
- **回溯时务必撤销染色**——这是回溯法最容易错的地方；
- 参考规模：约 20 行。

### `three_color_mrv(n, adj, stats, forward_check=False) -> list[int] | None`（Advance C1）

在任务二的基础上加两件事：

1. **MRV**：每步选择"当前可用颜色数最少"的未染色顶点；平局时取度数大的。注意"可用颜色"指的是不与已染色邻居冲突的颜色。
2. **前向检查**（`forward_check=True` 时开启）：染完顶点 v 的颜色 c 后，把 c 从 v 的所有未染色邻居的可用色集合中删除；若某邻居的可用色集合变空，立即撤销并回溯。

实现建议（二选一）：

- **现算法**：每步根据"已染色邻居"现算某顶点的可用色——简单直观，推荐先用它做对；
- **domains 法**：维护 `domains = [set({0,1,2}) for _ in range(n)]`，染色时同步收缩邻居的可用色——更接近 AC-3 等扩展的写法，但必须处理好"回溯时恢复现场"（每层复制一份最省事，本项目规模下完全够快）。

要点：

- MRV 只是**改变染色顺序**，不改变"尝试所有可能性"这一事实——所以它不会把可染的图判成不可染（完备性不变）。验收时会问为什么；
- 前向检查删除邻居可用色之后，**回溯时必须恢复**——建议删除前记下改动，或每层复制 domains（小图上复制完全够用，别过度设计）；
- `forward_check=False` 时应退化为"纯 MRV"，供对比实验分离两个优化的贡献；
- 参考规模：约 35 行。

## 5. 推荐实现顺序

1. 通读 `graph.py`，在 Python 里手动跑：`load_graph("data/triangle.txt")`，打印邻接表；
2. 任务一，先在纸上对五元环手动执行一遍交替染色；
3. 任务二，用 `data/triangle.txt` 和 `data/k4.txt` 一正一反调试，跑 `check.py`；
4. 在 `main.py gen` 生成的小图上观察 `stats["nodes"]` 随 n 增长；
5. Advance C1，先只做 MRV（`forward_check=False`），确认答案与任务二一致；再加前向检查；
6. 每一步都跑 `check.py`，不要攒到最后一起调。

## 6. 测试建议

`check.py` 的用例全部可以手算复核：

- **任务一**：四元环可二染色；三角形不可。
- **任务二**：三角形返回合法三染色（用 `is_valid_coloring` 验证）；K4 返回 `None`；`stats["nodes"] > 0`。
- **Advance C1**：Petersen 图可三染色；Grötzsch 图（`mycielski4.txt`）返回 `None`——这个实例很重要，它说明"难"不一定有显而易见的局部理由；同一随机图上 MRV+前向检查的节点数应**显著小于**朴素回溯。

调试时可观察的不变量：

- 任意时刻，已染色顶点之间的边两端颜色不同；
- 返回的方案一定能通过 `is_valid_coloring`；
- 同一实例上，三个求解器的答案（可染/不可染）必须一致；
- 撤销染色后，`coloring` 中不应残留"幽灵颜色"（建议未染色用 `-1` 哨兵）。

## 7. 常见错误

1. **忘记撤销染色**。回溯法的"回溯"二字就体现在这里；不撤销会把后续所有分支污染掉。
2. **冲突检查漏掉方向或检查未染色邻居**。邻接表是双向的，查 `adj[v]` 即可；未染色邻居（颜色为哨兵值）不应参与冲突判断。
3. **图不连通时只搜了第一个连通分量**。任务一外层循环要覆盖所有顶点。
4. **MRV 每步选完顶点后，仍按 0..n-1 顺序递归**。MRV 的核心就是动态选择下一个顶点。
5. **前向检查删除后忘记恢复**。和撤销染色是同一类错误，一错就是答案都错。
6. **`stats["nodes"]` 忘了自增，或在三个函数里口径不一致**（一个按递归调用数、一个按尝试颜色数）——性能对比就失去意义了。
7. **递归深度问题**。Python 默认递归上限约 1000，n ≤ 几百时没问题；若探索大图，可 `sys.setrecursionlimit` 或改迭代。
8. **把"找不到解"和"不存在解"混为一谈**。搜索穷尽了所有分支才能返回 `None`；提前 `return None` 是致命错误。
