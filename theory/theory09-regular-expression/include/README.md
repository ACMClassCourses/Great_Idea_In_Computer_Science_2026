## 题面（可直接粘贴到 OJ 题目描述）

**题目描述**

有限状态机（DFA）是"只记住有限信息"的计算模型：它从初始状态出发，每读入一个字符就按转移表跳到下一个状态；读完全部输入后，若停在某个接受状态，输入串就被接受。

在本题中，字母表固定为 `{0, 1}`，状态编号为 `0 … n-1`。给定一台 DFA 的完整描述和若干个二进制串，请逐个判断该 DFA 是否接受它。

提示：课程项目中"判断二进制数能否被 3 整除""判断字符串是否以 01 结尾"都是 DFA 的特例——状态机本身不同，模拟方法完全一样。本题就是把它们一般化。

**输入格式**

```text
n s k
a1 a2 … ak
z0 o0
z1 o1
…
z_{n-1} o_{n-1}
q
word_1
word_2
…
word_q
```

- 第一行三个整数 `n s k`：状态数 n（状态编号 0 … n-1），初始状态 s，接受状态数 k；
- 第二行 k 个整数：所有接受状态的编号（**k = 0 时该行为空行**）；
- 随后 n 行：第 i+3 行两个整数 `z o`，表示状态 i 读到 `0` 转移到 z、读到 `1` 转移到 o。转移表是完整的，不存在未定义的转移；
- 随后一行一个整数 q：查询串个数；
- 随后 q 行，每行一个由 `0`/`1` 组成的串。**串可能为空（空行），表示空串 ε**：此时状态机没有读入任何字符，停在初始状态。

**输出格式**

每个查询串输出一行：`YES` 表示接受，`NO` 表示拒绝。

**样例输入 1**（模三状态机：接受所有能被 3 整除的二进制串）

```text
3 0 1
0
0 1
2 0
1 2
5
0
11
110
10
1001
```

**样例输出 1**

```text
YES
YES
YES
NO
YES
```

说明：状态 i 表示"当前余数为 i"；读 0 转到 (2i) mod 3，读 1 转到 (2i+1) mod 3。`110` = 6、`1001` = 9 都能被 3 整除，`10` = 2 不能。

**样例输入 2**（接受所有以 01 结尾的二进制串）

```text
3 0 1
2
1 0
1 2
1 0
4
10101
11001
11100
01
```

**样例输出 2**

```text
YES
YES
NO
YES
```

**数据范围与提示**

- 1 ≤ n ≤ 1000，0 ≤ s < n，0 ≤ k ≤ n，1 ≤ q ≤ 100000；
- 0 ≤ 单个查询串长度 ≤ 10⁶，所有查询串总长度 ≤ 2×10⁶；
- 语言：Python 3，仅标准库。建议实现复杂度：每次转移 O(1)，总复杂度 O（输入总字符数）；
- 评测为全文精确比较：每个查询恰好一行 `YES`/`NO`，文件末尾有换行；
- 容易忽略的点：**空串查询**（空行）必须正确处理；k=0 时第二行为空行；k=n 时所有状态都是接受状态。

## 上传与打包说明

1. 在 OJ 后台新建题目（建议标题「有限状态机模拟器」），语言限定 Python 3，粘贴上方题面；
2. 测试数据用「数据 (zip)」上传，**格式要求严格**（见 OJ 官方帮助页「如何创建数据包？」/ `/OnlineJudge/help/admin/data-format`）：**压缩包文件名必须是 `题号.zip`**（题号是数据库主键 id），且**包内顶层是以题号命名的文件夹**，文件放在其中：`题号.zip/题号/1.in`、…、`题号.zip/题号/config.json`（结构与 A+B 数据包 `1000.zip/1000/…` 一致）。`config.json` 缺失或路径不对会报"需要 json 文件"之类的错误。在本目录执行（把 `<ID>` 换成实际题号，**两处都要换**）：

   ```bash
   cd testcases && mkdir -p <ID> && cp *.in *.out config.json <ID>/ && zip -r ../<ID>.zip <ID> && rm -rf <ID>
   ```

   若使用「数据（GUI）」上传，则逐点上传 `.in`/`.out` 并按 `config.json` 手工建组：simple（1–4）25 分、complex（5–9）35 分、large（10–12）25 分、robust（13–15）15 分；所有测试点时限 2000 ms，内存均 256 MiB，无需 SPJ（`SPJ: 0`）；
3. 如需重新生成或调整测试点，运行 `python3 ta/include/gen_testcases.py include/testcases`（生成器用独立的字典式转移表实现计算答案，与列表式参考答案交叉验证），随后 `bash ta/include/verify_testcases.sh` 逐点做字节级 diff 与计时。

## 测试点一览

| 编号 | 分组 | 考查点 |
| --- | --- | --- |
| 1 | simple | 实验一的模三机，8 个短串全部可手算（含 0、11、110、1001 等 README 原例） |
| 2 | simple | 实验二的"以 01 结尾"机，8 个短串（含 01、001、11001 等 README 原例） |
| 3 | simple | 单状态自环机：接受一切二进制串 |
| 4 | simple | 两状态奇偶机：`1` 的个数为偶数才接受 |
| 5 | complex | 模五机（5 状态），40 个中等随机串 |
| 6 | complex | "不含子串 101"机（含死态），随机串 + 手工构造的贴边串 |
| 7 | complex | 多接受状态 + 两个不可达状态（干扰项） |
| 8 | complex | 模三机上的长串（长度 1000）：全 0、全 1、交替、随机、末尾翻转 |
| 9 | complex | "以 00 开头且以 11 结尾"机（6 状态含死态），边界前缀/后缀组合 |
| 10 | large | 模一千机（n=1000），q=10000 个中等随机串 |
| 11 | large | 模三机上的超长串：两条合计约 2×10⁶ 字符，外加短串与空串 |
| 12 | large | q=100000 个短串压在"以 01 结尾"机上（考查 I/O 与常数） |
| 13 | robust | 空串查询：初始状态恰为接受状态，空串必须输出 YES |
| 14 | robust | k=0 无接受状态：含空串在内全部 NO |
| 15 | robust | k=n 全部接受：含空串在内全部 YES |

参考答案本机实测：全部 15 点通过，最慢测试点（11 号，约 2×10⁶ 字符）约 170 ms（含解释器启动），远低于 2000 ms 时限。
