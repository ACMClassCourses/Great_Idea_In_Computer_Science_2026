# RSA：Basic（基础阶段）— 为什么公钥可以公开

## 项目介绍

如果发送者和接收者使用同一把秘密钥匙加密、解密，就要先想办法安全地分享这把钥匙。RSA 提供了另一种思路：接收者公开用于加密的参数（公钥），让任何人都能加密消息；同时保留用于解密的秘密参数（私钥）。这里的“钥匙”是一组数字。RSA 是公钥密码学中的经典例子，它把素数、求余数和程序计算快慢的问题连接起来。

本阶段重点是理解与手算，**不要求编写完整 RSA 程序**。建议安排 **1 周，约 10–20 小时**。需要知道整数、素数和余数；素数是大于 1、正因数只有 1 和自身的整数，例如 2、3、5。最大公因数、模逆和欧拉（Euler）定理可随项目学习。

完成后，你应能解释密钥（加密或解密所用的参数）怎样生成、怎样参与运算，并区分“按规则加密后能正确解密”与“没有私钥的人难以恢复消息”。

## 简要算法介绍

先认识公式中的记号：

- `a mod n` 是 a 除以正整数 n 的余数，结果在 0 到 n−1 之间。例如 `17 mod 5 = 2`。“取模”就是求这个余数；Python 中写作 `a % n`。
- `a ≡ b (mod n)` 读作“a 与 b 模 n 同余”，即它们除以 n 的余数相同，例如 `17 ≡ 2 (mod 5)`。
- `gcd(a,b)` 是 a、b 的最大公因数；它为 1 时称两数“互素”，例如 8 与 15 互素。
- 若 `(e×d) mod N = 1`，就称 d 是 e 模 N 的“模逆”，也叫“模逆元”。它的作用类似倒数：与原数相乘、取模后得到 1。例如 `3×5 mod 7 = 1`，所以 5 是 3 模 7 的逆。这里 N 只是泛指取模时的除数；RSA 求 d 时使用的除数是下文的 `φ(n)`，不是 n。
- `φ(n)` 是“欧拉函数”在 n 处的值，φ 是希腊字母，读作 phi。它统计从 1 到 n 中与 n 互素的整数个数。例如 `φ(8)=4`，因为 1、3、5、7 与 8 互素。当 `n=p×q` 且 p、q 是不同素数时，`φ(n)=(p−1)(q−1)`。
- `m^e` 表示 m 的 e 次方；连续字母 `ed`、`pq` 分别表示乘积 `e×d`、`p×q`。Python 的乘方写作 `**`，不是 `^`。

RSA 的流程如下。m 表示加密前的整数消息（明文），c 表示加密后的整数（密文）；e 是加密时的指数，d 是解密时的指数，n 是加密、解密时取余所用的除数，叫作“模数”。

| 步骤 | 操作 | 含义 |
| --- | --- | --- |
| 选择素数 | 不同素数 p、q | 保密 |
| 计算模数 | `n=pq`，`φ(n)=(p−1)(q−1)` | n 可以公开；φ(n) 要保密 |
| 选择指数 | `1<e<φ(n)` 且 `gcd(e,φ(n))=1` | 保证 e 的模逆存在 |
| 求私钥指数 | 找到 `1≤d<φ(n)`，使 `ed≡1 (mod φ(n))` | 得到解密所用的指数 d |
| 加密 | `c=m^e mod n` | 使用公钥 (n,e) |
| 解密 | `m=c^d mod n` | 使用秘密 d |

消息必须先表示为 `0≤m<n` 的整数，本阶段直接从这样的整数开始，不要求把文字转换成整数。公钥是 `(n,e)`，可告诉他人；d、p、q 和 φ(n) 都要保密。解密时需要 n 和 d；实际私钥还常保存 p、q，以加快计算。

### 为什么可以还原

加密再解密，相当于计算 m 的 `e×d` 次方后对 n 取余。这里用到一个余数运算的性质：乘法过程中先取余，不会改变最后的余数。例如 `(7×7) mod 5` 与 `(2×2) mod 5` 都是 4，因为 `7 mod 5 = 2`。

欧拉定理说：若 m 与 n 互素，则 `m^φ(n)≡1 (mod n)`，也就是 m 的 φ(n) 次方除以 n 的余数为 1。本阶段可使用这一定理，不要求证明它。选择 d 的条件保证 `ed−1` 是 φ(n) 的整数倍，即 `ed=1+tφ(n)`，其中 t 为非负整数。因此：

```text
m^(ed) = m^(1+tφ(n)) = m × (m^φ(n))^t
对 n 取余后，右边相当于 m × 1^t，也就是 m。
```

欧拉定理要求 m 与 n 互素，例如 m 是 p 的倍数时就不能直接使用它。这样的消息仍能正确还原，但要分别检查除以 p、q 的余数再作证明，完整过程放到 Advance。Basic 只需说清上述推理在哪一步用了互素条件，不要求先学完后面的定理。

## 三项任务

### Q1：公钥和私钥怎样产生？

写出密钥生成流程，解释互素条件和模逆，明确哪些量公开、哪些量保密。使用下面的手算样例：

```text
p = 61，q = 53
n = 3233，φ(n) = 3120
e = 17，d = 2753
m = 65，c = 2790
```

核对乘积、互素条件和 `17×2753 = 1 + 15×3120`。可以用辗转相除法检查互素：反复将较大数除以较小数，再用除数除以余数，直到余数为 0，最后一个非零余数就是最大公因数。Basic 可直接使用给出的 d，但要验证它，求 d 的通用算法放到 Advance。

### Q2：为什么加密后能解密？

记录 `65^17 mod 3233` 和 `2790^2753 mod 3233` 的计算过程。可用反复平方，只保留每一步余数，不必展开巨大整数：

```text
17 = 16 + 1
先算 65^2、65^4、65^8、65^16 对 3233 的余数，
再把所需余数相乘并取模。
```

第一步为 `65^2 mod 3233 = 992`，之后将上一步的余数平方再取模。解密时可使用 `2753 = 2048+512+128+64+1`，按同样方法列表计算，只乘上这些指数对应的余数。

说明消息 m 与 n 互素时为什么能还原，并指出其余消息还需分别讨论除以 p、q 的余数。计算器或 Python 可作核验，但提交要体现你的推演。

### Q3：正确性证明是否说明 RSA 安全？

写一段简短说明，包含：

- 正确性说明按规则生成密钥、执行加密后可以正确解密，不代表没有私钥的人无法恢复消息。
- 如果能把 n 分解为 p、q，就能求 φ(n) 和 d，从而解密。但这不证明“任何解密方法都必须先分解 n”。
- 直接套用本节公式的做法称为“原始 RSA”。它是确定性的，即使用同一公钥加密同一消息，总会得到同一密文。别人若猜测消息只有几种可能，就能自行加密这些候选消息，与密文比较，所以不能直接用这两条公式保护真实消息。
- 数字签名让持有私钥的人为消息生成一份可核验的数据，其他人用公钥检查这份签名是否与消息匹配。它可以帮助确认消息是否被改动，以及是否由对应私钥的持有者签署，但不隐藏消息内容；要确认签名者的身份，还需可靠地确认公钥属于谁。

这些小参数很容易分解，只用于学习，不能用来保护真实数据。

## 算法发展历程

| 时间 | 发展 | 解决或提出的问题 |
| --- | --- | --- |
| 公钥密码以前 | 对称加密（双方使用同一秘密密钥） | 怎样提前把密钥安全地交给对方成为难题 |
| 1976 年 | Diffie 与 Hellman 公开公钥密码思想和密钥协商 | 双方能否通过公开交换的信息算出同一秘密？这与直接加密消息是不同的任务 |
| 1977 年提出，1978 年发表 | Rivest、Shamir、Adleman 的 RSA | 用“乘方后取余”和秘密信息构造加密、签名所需的基本运算 |
| 后续 | OAEP 加密编码、PSS 签名编码等方案与标准 | 除乘方取余外，还规定怎样组织消息、加入随机数据和检查结果；名称和细节在 Advance 学习 |

后来的量子算法表明，未来若有足够大且可靠的量子计算机，分解 RSA 的模数可能变得容易。Basic 只需了解这一背景，相关讨论放在 Advance。RSA 的意义不只是两条公式，还在于帮助我们区分“能正确还原”与“能保护消息”。真实系统必须采用成熟的密码方案和实现。
