# theory-3：函数式编程

## A 问题是什么

一个程序可以被写成一连串修改变量的命令，也可以被写成小函数之间的组合。如果尽量避免共享可变状态，能否更容易解释程序的含义、测试局部行为，并把正确性推理分解为较小步骤？函数式编程围绕纯函数、不可变数据与组合展开，为组织计算提供了另一种思路。

本项目分 Basic 与 Advance 两个阶段。Basic 只需完成第 1 周内容：使用 Haskell 理解纯函数、递归、模式匹配与高阶函数；Advance 完成其余内容：代数数据类型、类型类、惰性求值、显式处理副作用与性质测试，并完成一个小型程序。可参考 v0 中改编自 CIS 194 的教学资料，不要求完成整门课程的全部作业。

| 阶段 | 工作量安排 | 完成后的能力 |
| --- | --- | --- |
| Basic | 一周内约 10–20 小时 | 能阅读简单类型签名，用递归和 map/filter/fold 表达列表计算 |
| Advance | 完成 Basic 后，再用六周推进（总计七周）；建议难度系数 1.0，以 project1 的 1.0 为基准 | 能用类型和函数组合建模，区分纯计算与 IO，完成带测试的小型项目 |

两个阶段都不需要掌握整门 Haskell 课程。Basic 的“简易”指理解纯函数和基本列表变换，不要求 Monad 精通。

### Basic：纯函数、递归与组合

Basic 的核心概念包含：纯函数、引用透明性、不可变数据、递归、模式匹配、高阶函数。完成 Basic 时，须按 **Q1–Q3** 提交简短回答。

| 编号 | 需要回答的问题 | 回答应包含的内容 |
| --- | --- | --- |
| Q1 | 什么是纯函数与引用透明性？ | 纯函数不产生可观察副作用；对相同输入有相同的计算行为；纯表达式可用其等价结果替换，但不保证所有函数都会终止 |
| Q2 | 不修改循环变量，怎样处理一个列表？ | 用空列表和非空列表的模式匹配定义递归；说明基本情况、递归参数如何缩小及结果如何组合 |
| Q3 | map、filter、fold 分别抽象了什么？ | map 逐元素变换，filter 按条件保留元素，fold 把结构逐步汇总；给出类型签名或输入输出示例 |

**关键区分：**
- 函数式编程不是“所有地方都写匿名函数”，而是围绕值、函数和组合组织程序。
- 不可变数据不等于没有状态；状态可以作为参数传入，并作为新值返回。
- 静态类型能排除一部分错误，但不能保证算法正确、运行终止或没有资源问题。
- Haskell 用 `IO` 表达与外部世界的交互；“纯函数式”不表示不能读文件或打印内容。

#### 3 Basic 小练习

在 GHCi 中完成“保留偶数并求平方和”，分别写递归版本和组合版本，说明它们的结果为什么一致。

```haskell
sumEvenSquares :: [Integer] -> Integer
sumEvenSquares xs = sum (map (\x -> x * x) (filter even xs))
```

测试空列表、含负数的列表和普通整数列表，说明选择 `Integer` 与固定精度 `Int` 的区别。提交 Q1–Q3、两种实现及运行记录；不要求在第一周掌握 Monad。

提交 Q1–Q3 的简短回答、两种实现（递归版本和组合版本）的运行记录，以及测试结果。

### Advance：类型、惰性与可组合程序

Advance 在 Basic 基础上讨论如何让数据结构、错误处理与外部交互都具有清晰的接口。

建议完成以下任务：

1. 选择 v0 中与基础列表、递归及代数数据类型相关的练习，完成至少三个有解释的例子。
2. 定义二叉树或简单表达式树，使用模式匹配实现遍历、求值或统计。
3. 用 `Maybe` 或 `Either` 表示解析失败、空输入等情况，减少依赖未处理异常或部分函数。
4. 比较 `foldr`、`foldl` 与严格折叠 `foldl'`，用有限列表和惰性列表解释求值差别。
5. 把小程序拆成“读取输入、纯计算、输出结果”三个部分，使核心算法能够独立测试。
6. 给出单元测试与至少三条性质测试，说明测试通过为什么仍不等于数学证明。
7. 整理研究报告与 presentation，用一个重构前后对照说明函数式抽象带来的收益与成本。

### 概念与能力边界

| 概念 | 要解决的问题 | 需要展示的例子 | 需要避免的误解 |
| --- | --- | --- | --- |
| 代数数据类型 | 精确表达数据有哪些形态 | 空树与非空树；成功与失败 | 任意字符串标签不等于类型层面的约束 |
| 多态与类型类 | 复用操作，同时约束可用能力 | 列表长度的多态；带数值约束的求和 | 类型类不是面向对象继承的直接替代品 |
| 高阶函数 | 把变化的操作当作参数 | 用同一遍历框架完成多种变换 | 更短的表达式不一定更容易读 |
| 惰性求值 | 只计算当前结果需要的部分 | 从无限列表取有限前缀 | 惰性不保证更快，可能积累未求值表达式 |
| IO 与效果组合 | 明确外部交互及执行顺序 | 读文件后调用纯统计函数 | IO 类型不会自动证明程序安全或正确 |
| 性质测试 | 用许多生成样本检查规律 | 反转两次恢复原列表 | 有限随机测试不能覆盖所有输入 |

## 附录：问题的来龙去脉与发展过程

**从函数到计算模型。**  
λ 演算用函数抽象与应用描述计算，为函数式语言提供理论来源。项目中的列表变换和函数组合，是这一思想在日常编程中的具体形式。

**从表达式到程序结构.**  
Lisp 展示了以表达式组织计算的力量；后续语言逐步发展出类型推断、代数数据类型、模式匹配与惰性求值。不同语言采用不同组合，函数式编程并不等于某一种语法。

**从隐式状态到显式接口.**  
当共享变量被多个过程修改时，理解一个函数常常需要理解整段执行历史。纯函数把主要依赖放到参数中，让局部推理更直接；与外部世界交互时，则需要明确描述效果与顺序。

**从语言特性到软件设计.**  
函数式思想也能在其他语言中使用，例如不可变配置、无副作用的数据变换与流水线组合。最终要比较的是可读性、可测试性与资源成本，而不是把某种编程范式视作所有问题的统一答案。
