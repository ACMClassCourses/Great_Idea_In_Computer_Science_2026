# 系统3:迷你 Shell：用 C++ 模拟命令与工具组合

## A 问题是什么

用户输入一行命令后，Shell 怎样理解它、找到操作对象，并把多个工具连接起来？本项目用 C++ 编写一个交互式模拟器，所有目录、文件和文本都保存在 STL 数据结构中。Basic 从单层目录和简单文件命令开始；Advance 增加目录树、路径解析、管道与重定向，并学习 Shell 的用法和工具组合思想。程序不调用系统 Shell，不创建子进程，也不操作电脑上的真实文件，退出后虚拟数据可以清空。

| 阶段 | 工作量 | 难度 | 主要成果 |
| --- | --- | --- | --- |
| Basic | 一周约 10–20 小时 | easy | 能创建、读写和列出虚拟文件的交互程序 |
| Advance | Basic 后追加六周 | medium | 支持目录树、路径、管道与重定向的模拟 Shell |

前置知识：C++ 条件、循环、字符串与数组；`map` 的用法可以边做边学。难度按背景、实现、调试和解释要求综合标注：easy 为明确步骤的单项任务，medium 需要组合多个状态或机制，hard 需要理解更复杂的系统行为。可选阅读不要求增加代码。

#### 2 代码任务与边界

用 `map<string, string>` 保存“文件名 → 内容”。启动时只有一个虚拟根目录 `/`；Basic 不需要子目录，文件名限定为非空的英文字母、数字、下划线、点和连字符，且不能是 `.` 或 `..`。用 `getline` 逐行接收命令，直到 `exit` 或输入结束。

| 命令 | 必须实现的行为 |
| --- | --- |
| `pwd` | 输出 `/` |
| `ls` | 按文件名字典序列出文件，每行一个；空目录不输出条目 |
| `touch 文件名` | 文件不存在则创建空文件，已存在则保持内容 |
| `cat 文件名` | 输出已有文件的完整内容，不额外追加换行 |
| `echo [参数...]` | 参数用一个空格连接，末尾加换行；无参数只输出换行 |
| `echo [参数...] > 文件名` | 将 echo 的输出覆盖保存，文件不存在则创建；不显示该输出 |
| `exit` | 结束程序 |

Basic 只要求 `echo` 后的这一种输出重定向。词与操作符用空格分隔，暂不处理引号、转义、变量、通配符。成功的创建、写入不输出提示；未知命令、缺少参数、非法文件名、文件不存在或多余参数输出一行 `ERROR`，随后继续运行。可以有交互提示符，但测试模式须关闭。

演示输入：

```sh
touch a.txt
echo hello shell > a.txt
touch a.txt
cat a.txt
ls
pwd
exit
```

预期依次输出 `hello shell`、`a.txt`、`/`，各占一行。再测试空文件、空目录、重复创建、覆盖写入和错误命令后继续执行。

#### 2 实现要求

目录树节点保存名称、类型和父节点；目录保存子节点，文件保存字符串。可以使用节点编号和 `vector`，无需复杂的继承设计。启动时建立 `/`，所有操作沿用 Basic 的内存模拟方式。

- 路径支持绝对路径、相对路径、`.`、`..`；根目录的父目录仍是根目录。`.`、`..`、`/` 表示路径含义，不是独立命令。
- `mkdir 路径`：父目录须已存在；重名或文件、目录类型冲突时报错。
- `cd 路径`：只能进入已有目录；`pwd` 输出当前目录的绝对路径。
- `ls [目录]`：默认当前目录，按字典序列出直接子条目，不递归。
- `touch 文件`、`cat [文件...]`、`echo [参数...]` 保留 Basic 语义；`cat` 的多个文件依次连接，无文件参数时原样输出传入文本。
- `tee 文件`：把传入文本覆盖保存，同时返回同一份文本作为输出。`tee`、`>` 可以创建新文件，但父目录须已存在，不能覆盖目录。

管道通过函数之间传递字符串实现。先完整检查组合语法，再从左到右执行；中间结果不直接打印，最终结果才显示或重定向。只支持第一条命令的 `< 文件` 与最后一条命令的 `> 文件`，各最多一次；只用空格分词。`cd`、`exit` 仅支持独立执行。无上游或 `<` 时，输入文本为空。错误单独显示并停止本次组合，不把错误文本传给下游；无需回滚已成功的 `tee` 等操作，执行错误的命令单独输出一行 `ERROR`。

```sh
mkdir docs
cd docs
echo hello minishell > a.txt
cat < a.txt | tee b.txt | cat > c.txt
cat c.txt
cd ..
pwd
```

预期只输出 `hello minishell` 与 `/` 两行；`docs` 下三个文件内容一致。另测根目录的 `..`、嵌套相对路径、文件与目录同名冲突、空管道段、缺少重定向文件名及中途失败。

## C 问题的来龙去脉与发展过程

早期 Unix 的命令解释器让用户用文本组织程序执行；随着工具增多，管道把一个程序的输出变成另一个程序的输入，使简单工具能够组合工作。项目中的命令分派与字符串传递分别对应这两层思想。[Dennis Ritchie：Unix 历史回顾](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/hist.html)

Bourne Shell 及后续 Bash 把命令组合发展为包含变量、判断和循环的脚本环境。学习 Shell 因而既包括使用命令，也包括理解统一接口如何支持自动化。[GNU Bash：What is Bash?](https://www.gnu.org/software/bash/manual/html_node/What-is-Bash_003f.html)
