## A 问题是什么

当较快的存储空间有限，而需要访问的数据很多时，系统应该保留哪些内容、淘汰哪些内容？页置换与缓存替换都涉及这个问题。本项目分为 Basic 与 Advance 两个阶段：Basic 了解缓存的用途，并用 C++ 实现 FIFO 模拟器；Advance 在已有程序上增加 LRU、CLOCK，通过结果分析和阅读理解不同策略的取舍，以及它们与操作系统内存管理的联系。两个阶段都用数组或链表保存编号，重点是理解思路和模拟过程。

| 阶段 | 工作量安排 | 难度 | 完成后的能力 |
| --- | --- | --- | --- |
| Basic | 一周内约 10–20 小时 | easy | 解释缓存与 FIFO，用 C++ 通过一道 FIFO 模拟 OJ 题 |
| Advance | 完成 Basic 后，再用六周推进 | medium；可选方向含 hard 任务 | 实现并比较三种策略，解释结果，了解相关系统思想 |

Advance 复用 Basic 的 FIFO 代码，增加 LRU、CLOCK、过程展示和对比统计。两个阶段均不需要操作真实内存、实现页表或搭建图形界面。

#### 3 代码任务：通过一道 FIFO 模拟 OJ 题

用 C++ 完成 ACM Class OnlineJudge 题目 **3275. FIFO Cache Simulator**，获得 Accepted（AC）。也可参考 [洛谷 P1540「机器翻译」](https://www.luogu.com.cn/problem/P1540) 理解相同的 FIFO 模拟思想，但不要求在两个平台重复提交。

OJ 3275 的输入输出要求如下：

- 输入：第一行是缓存容量 C 和访问次数 N，第二行是 N 个非负整数编号；`1 <= C, N <= 100`，编号在 `int` 范围内。
- 模拟：每个编号占一个缓存位置，缓存初始为空，依次按 FIFO 处理访问。
- 输出：一个整数，表示总未命中次数。

使用数组、`std::vector` 或链表即可，允许线性查找。按“最早进入 → 最晚进入”保存缓存顺序，逐个处理访问：

1. **命中：** 编号已经在缓存中，FIFO 的顺序保持不变。
2. **未命中且有空位：** 未命中次数加一，把新编号加入末尾。
3. **未命中且已满：** 未命中次数加一，淘汰最早进入的编号，再把新编号加入末尾。

提交 OJ 3275 的程序严格按题面输出答案。Basic 的代码不要求输出每一步状态或命中率；手工推演过程放在简短说明中即可。

**命中不会让 FIFO 中的对象重新排队；未命中也不一定发生淘汰，填充空位同样算未命中。**

#### 4 用一个小例子核对

容量为 3，依次访问 `1 2 3 1 4 2 5`：

| 访问编号 | 结果 | 淘汰对象 | 缓存顺序：最早进入 → 最晚进入 |
| --- | --- | --- | --- |
| 1 | 未命中 | 无 | [1] |
| 2 | 未命中 | 无 | [1, 2] |
| 3 | 未命中 | 无 | [1, 2, 3] |
| 1 | 命中 | 无 | [1, 2, 3] |
| 4 | 未命中 | 1 | [2, 3, 4] |
| 2 | 命中 | 无 | [2, 3, 4] |
| 5 | 未命中 | 2 | [3, 4, 5] |

最终命中 2 次、未命中 5 次，程序应输出 `5`。上表用于手算核对，不是 OJ 要求的输出。再检查容量为 1、连续访问同一编号、所有对象都能装入等情况。

**G1、G5 的学习重点：**

认识页面、页框、页表和缺页：页面是虚拟地址空间的划分单位，页框是对应的物理内存空间，页表记录映射关系。结合这些概念理解为什么需要页面置换。在本项目的简化分页模型中，可以用页面编号作为访问对象，将未命中次数作为缺页次数；页表与地址转换只要求理解。[OSTEP：分页介绍](https://pages.cs.wisc.edu/~remzi/OSTEP/vm-paging.pdf)

进一步学习如何评价替换策略：

- **利用访问历史：** FIFO、LRU、CLOCK 分别保存了什么信息，怎样影响淘汰决定？
- **理想比较基准：** 了解 OPT 为什么选择未来最晚才会再次访问的页面，以及现实系统为什么通常无法预知未来。OPT 不要求实现。
- **容量与访问模式：** 了解 Belady 异常，思考为什么增加容量不一定让 FIFO 的缺页次数减少。
- **维护成本：** 命中率之外，记录访问顺序、更新访问位和寻找淘汰对象需要付出什么成本？

讲解时结合具体访问序列说明原因。[OSTEP：页面置换策略](https://pages.cs.wisc.edu/~remzi/OSTEP/vm-beyondphys-policy.pdf)

#### 3 算法实现与过程展示（G2–G4）

| 算法 | 命中时 | 缓存已满且未命中时 | 简单实现方式 |
| --- | --- | --- | --- |
| FIFO（复用 Basic） | 顺序不变 | 淘汰最早进入的对象 | 数组或队列 |
| LRU | 更新为最近使用 | 淘汰最久未访问的对象 | 数组记录最后访问的步骤编号，或链表调整顺序 |
| CLOCK | 将该位置的访问位设为 1，指针不动 | 循环检查访问位，清除并跳过 1，选择遇到的 0 | 固定数组、访问位和一个指针下标 |

可将三种算法分别写成函数，使用相同输入与统计方式。数组扫描和顺序查找都可以，不要求特定时间复杂度或复杂的类设计。

在 OJ 程序的基础上，增加本地运行时的过程展示：每次输出访问编号、是否命中、淘汰对象和更新后的缓存状态，最后统计命中次数、未命中次数及命中率。命中率为命中次数除以总访问次数。

CLOCK 统一采用以下规则，便于手算和核对：

1. 指针初始为 0；未满时按下标从小到大填入空位，访问位设为 1，指针移到下一位置。填满后指针回到 0。
2. 命中时只将对应访问位设为 1，指针不动。
3. 已满且未命中时，从指针处检查：遇到 1，清为 0 并前进；遇到 0，在该位置淘汰旧对象。
4. 装入新对象，访问位设为 1，指针前进一格；到末尾后回到开头。

例如，缓存为 `[1, 2, 3]`、访问位为 `[1, 1, 1]`，指针在下标 0。访问 4 时，扫描一圈清零，再淘汰 1；结果为 `[4, 2, 3]`、访问位 `[1, 0, 0]`，指针指向下标 1。运行 CLOCK 时应一并展示访问位和指针位置。

#### 4 比较算法并解释结果（G5 · medium）

每次比较都使用相同容量、相同访问序列，三个算法分别从空缓存开始。对 Basic 第 4 节容量为 3、序列为 `1 2 3 1 4 2 5` 的示例，FIFO、LRU、CLOCK 的未命中次数应分别为 5、6、5。

自行准备几组短序列，覆盖反复访问少量对象、循环访问超过容量的对象、访问热点发生切换等情况。改变容量，整理三种算法的命中与未命中次数。手写序列和文本表格即可，重点解释不同决策为什么产生不同结果。

用 FIFO 运行 `1 2 3 4 1 2 5 1 2 3 4 5`，容量为 3 时缺页 9 次，容量为 4 时缺页 10 次，观察 Belady 异常。一次实验的结果不能说明某个算法在所有访问模式下都更好。

## C 问题的来龙去脉与发展过程

**从有限的快速存储到自动管理。** 快速存储容量有限，程序又希望方便地使用更多空间。1962 年介绍 Atlas 的《One-Level Storage System》展示了将快速存储与磁鼓存储自动协调起来的设计，使程序能够通过统一的存储视图工作。页面何时调入、哪些页面应被保留，成为系统需要解决的问题。[Atlas 原论文](https://www.chilton-computing.org.uk/acl/pdfs/atlas-1-level.pdf)

**从替换规则到效果与开销的比较。** FIFO 依据进入顺序，LRU 利用访问历史，CLOCK 通过访问位近似记录近期使用情况。OPT 提供理想比较基准，Belady 异常则说明直觉也需要验证。理解这些方法时，需要同时关注访问模式、缺页次数和维护记录的成本。[OSTEP：置换策略的发展与比较](https://pages.cs.wisc.edu/~remzi/OSTEP/vm-beyondphys-policy.pdf)

**从单次淘汰到程序整体的内存需求。** Denning 在 1968 年发表工作集模型论文，将近期访问的页面集合与程序的内存需求联系起来。研究因此还需要考虑为程序保留多少内存，以及需求超过资源时如何避免过度换页。选学工作集方向时，可以沿这条思路进一步阅读。[工作集模型原论文](https://doi.org/10.1145/363095.363141)

**面向真实系统继续发展。** 页面是否被修改、记录访问的成本以及不同工作负载，都影响实际回收效果。Linux 的 Multi-Gen LRU 是进一步研究页面组织与回收的例子。本项目通过简单模拟掌握基本决策，再通过选读理解真实系统增加机制的原因。[Linux Multi-Gen LRU](https://docs.kernel.org/mm/multigen_lru.html)
