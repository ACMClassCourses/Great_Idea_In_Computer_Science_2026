# LZW 压缩：Basic（基础阶段）

## 1. 项目目标

你将编写一个简单的 LZW 编码程序：读入只含大写字母的字符串，给读到的片段建立编号，再用编号表示原文。把原文转换成编号叫“编码”，从编号还原原文叫“解码”。本阶段先完成编码，重点是把“发现重复片段—给片段编号—继续使用编号”的过程写清楚、写正确。

完成后，你应该能够：

- 解释无损压缩（还原后与原文完全相同）为什么必须能够逐字符恢复原文；
- 手算 LZW 的字典变化和输出编号；
- 独立实现编码循环：从当前位置开始，尽量找出字典中已有的最长片段；
- 用空输入、单字符等容易出错的特殊情况检查程序，这类检查也叫“边界测试”。

预计用时：1 周，约 10–16 小时，可预留到 20 小时。先修要求：会使用 C++ 的循环、字符串和基本输入输出；如何保存“字符串与编号的对应关系”可以随项目学习。本阶段不要求解码、二进制压缩文件或课堂展示。

## 2. LZW 在做什么

这里的“字典”是一张字符串与整数编号的对应表，例如 `AB→26` 表示片段 `AB` 的编号是 26，一条对应关系叫一个“词条”。初始字典固定为 `A→0, B→1, ..., Z→25`，新词条依次使用 26、27、28 等编号。

从左到右读取输入时，`w` 保存当前已经匹配到的片段；每读入一个字符 `c`，就尝试把它接到 `w` 后面。`w+c` 表示字符串拼接，例如 `"AB"+"A"` 得到 `"ABA"`。只要拼接后的片段还在字典中，就继续延长 `w`。下面用文字和变量名描述算法步骤，称为“伪代码”，不需要按原样编译。空输入直接输出空行；非空输入执行：

```text
next_code = 26（下一个新词条的编号）
w = 第一个字符
依次读取后面的字符 c：
    如果 w+c 在字典中：
        w = w+c
    否则：
        输出 w 的编号
        把 w+c 加入字典，使用 next_code 作为编号
        next_code = next_code + 1
        w = c
循环结束后输出 w 的编号
```

例如输入 `ABABABA` 时，新增词条依次为 `AB→26`、`BA→27`、`ABA→28`，输出为：

```text
0 1 26 28
```

最后的 `ABA` 必须在循环结束后单独输出。输出编号是本阶段的“编码结果”，编号之间用空格分隔。现在打印的数字只是便于核对的文字；若要判断是否节省空间，还要规定每个编号占多少存储空间。

## 3. 编程任务

使用 **C++17** 独立编写程序。输入是一行长度不超过 1000 的大写英文字母串，不含空格，输出一行编号序列。读到空行或没有读到任何字符时，都输出空行；行末的换行符不属于待编码的内容。可使用 `std::getline` 读取整行，以便处理空行。不查询空字符串的字典编号。

可以使用 `std::map<std::string, int>` 或 `std::unordered_map<std::string, int>` 保存字典：用字符串查找编号，并能插入新的对应关系。暂时不限制字典容量，也不用实现解码器。程序正常打印的内容（标准输出）只能包含答案；检查程序时临时打印的字典变化等信息，请另行记录在报告中。

请自行设计测试输入，并根据手算结果核对程序输出；至少覆盖空输入、单字符（如 `A`）、连续重复字符（如 `AAAAAA`）、没有重复片段（如 `ABCDEF`），以及循环结束时 `w` 仍保存着未输出片段的情况（如 `ABABABA`）。

## 4. 你需要回答的问题

1. 无损压缩和有损压缩有什么区别？有损压缩允许丢弃部分细节，例如图片压缩后可能与原图略有不同。为什么本项目要求逐字符恢复？
2. LZW 字典中的“字符串”和“编号”分别代表什么？
3. `w+c` 已在字典和不在字典时，程序分别做什么？
4. 输出编号更少是否一定占用更少空间？例如，原文有 7 个字符，每个占 1 字节；编码后有 4 个编号，每个占 2 字节，哪一个更大？1 字节是计算机中常用的存储单位，等于 8 个二进制位，每一位只能是 0 或 1。
5. 手算 `ABABABA`，列出每次新增词条、输出编号和最后一次输出的原因。

## 6. 常见错误

- 把新词条加入字典后立刻输出新词条，导致输出时机错一位；
- 忘记循环结束后的最后一次输出；
- 把 `w+c` 不在字典理解成只输出 `c`；正确做法是输出 `w`，然后从 `c` 重新开始；
- 把屏幕上打印的数字个数或位数当成压缩后的大小；例如打印 `26` 需要两个文字字符，但编号 26 存成文件时占多少字节，要由存储规则决定；
- 为了打印调试信息修改标准输出，导致编号序列中多出额外文字。

## 7. 算法发展历程

1977 年的 LZ77 遇到重复片段时，会记录“往前找多远、复制多长”，而不再保存同一片段。例如“往前找 3 个字符，复制 3 个字符”就能引用刚出现过的 `ABC`。1978 年的 LZ78 改为边读输入边建立字符串字典。Welch 在 1984 年提出 LZW，在开始时就放入所有单字符，并设计了一致的更新规则，让编码器和解码器能够各自建立相同的字典。LZW 后来用于 GIF、TIFF 等图像格式。

后来的算法组合了多种方法：DEFLATE 先找重复片段，再用 Huffman（哈夫曼）编码给常见符号分配较短的 0、1 序列；LZMA 还会根据已读内容估计后续数据出现的可能性。Basic 只需理解这条思路变化，不要求掌握这些算法的细节。
