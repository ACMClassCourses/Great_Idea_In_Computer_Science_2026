# LZW 压缩：Basic

负责人：周学信，叶博文。

## 1. 项目目标

你将实现一个最小的 LZW 编码器：读入只含大写字母的字符串，建立字符串字典，并输出字典编号。这个阶段的重点不是做出一个通用压缩软件，而是把“发现重复片段—给片段编号—继续复用编号”的过程写清楚、写正确。

完成后，你应该能够：

- 解释无损压缩为什么必须能够逐字符恢复原文；
- 手算 LZW 的字典变化和输出编号；
- 独立实现“最长已知串”的编码循环；
- 用边界测试检查空输入、单字符、重复字符和末尾匹配。

预计用时：1 周，约 10–16 小时，可预留到 20 小时。先修要求：会使用 C++ 的循环、字符串和基本输入输出；字典映射可以随项目学习。本阶段不要求解码、二进制压缩文件或 presentation。

## 2. LZW 在做什么

编码器维护一个字典。初始字典固定为 `A→0, B→1, ..., Z→25`，新词条从 26 开始。扫描输入时，令 `w` 表示目前仍能在字典中找到的最长字符串，令 `c` 表示下一个字符。空输入直接输出空行；非空输入执行：

```text
w = 第一个字符
依次读取后面的字符 c：
    如果 w+c 在字典中：
        w = w+c
    否则：
        输出 w 的编号
        把 w+c 加入字典
        w = c
循环结束后输出 w 的编号
```

例如输入 `ABABABA` 时，新增词条依次为 `AB→26`、`BA→27`、`ABA→28`，输出为：

```text
0 1 26 28
```

最后的 `ABA` 必须在循环结束后单独输出。输出编号是本阶段的“编码结果”，编号之间用空格分隔；十进制文字并不是实际的二进制压缩文件。

## 3. 编程任务

使用 **C++17** 独立编写程序。输入是一行长度不超过 1000 的大写英文字母串，不含空格，输出一行编号序列。空输入输出空行；不查询空字符串的字典编号。

可以使用 `std::map<std::string, int>` 或 `std::unordered_map<std::string, int>`。暂时不限制字典容量，也不用实现解码器。程序的标准输出只能包含答案，调试信息请写到注释、报告或单独的演示模式中。

请自行设计测试输入，并根据手算结果核对程序输出；至少覆盖空输入、单字符、重复字符、无重复片段和末尾仍有匹配的情况。

## 4. 你需要回答的问题

1. 无损压缩和有损压缩有什么区别？为什么本项目要求逐字符恢复？
2. LZW 字典中的“字符串”和“编号”分别代表什么？
3. `w+c` 已在字典和不在字典时，程序分别做什么？
4. 输出编号更少是否一定占用更少字节？请比较“编号个数”和“编号的存储宽度”。
5. 手算 `ABABABA`，列出每次新增词条、输出编号和最后一次输出的原因。

## 6. 常见错误

- 把新词条加入字典后立刻输出新词条，导致输出时机错一位；
- 忘记循环结束后的最后一次输出；
- 把 `w+c` 不在字典理解成只输出 `c`；正确做法是输出 `w`，然后从 `c` 重新开始；
- 用十进制编号字符串的长度冒充压缩后大小；本阶段还没有规定编号的二进制存储格式；
- 为了打印调试信息修改标准输出，导致编号序列中多出额外文字。

## 7. 算法发展历程

LZW 不是凭空出现的。1977 年的 LZ77 用“向前看过的窗口中的距离和长度”表示重复片段；1978 年的 LZ78 改用逐步建立的短语字典。Welch 在 1984 年把 LZ78 的思想改造成适合工程实现的 LZW，并使用预置字符字典让编码器和解码器保持同步。LZW 后来用于 GIF、TIFF 等格式，也曾用于早期磁盘和图像工具。

之后的压缩格式开始组合多种思想：DEFLATE 把 LZ77 的重复片段引用与 Huffman 编码结合，LZMA 则加入更大的字典和概率模型。学习 LZW 的意义，是先掌握一个清楚的字典同步机制，再理解现代压缩器为什么要同时处理“重复”和“符号频率”。
