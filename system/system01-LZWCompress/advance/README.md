# LZW 压缩：Advance — 从编号到无损还原

## 项目介绍

Basic 把大写字母串变成了字典编号。现在的问题是：解码器没有见过原文，也没有编码器留下的字典，它能否仅凭编号还原数据？你将把 LZW 扩展到任意字节，实现独立解码和固定宽度存储，再比较不同数据的实际压缩效果。

先修要求：完成 [Basic](../basic/README.md)，能解释字典更新与末尾输出；熟悉数组、字符串、映射以及基本文件或字节数组操作。建议在 Basic 后追加 **6 周**。允许用 C++17 的字符串映射和数组完成任务，真实文件读写为选做。

## 简要算法介绍

编码过程仍然是匹配最长已知串、输出编号、添加新词条。不同的是，初始字典包含所有单字节：`0–255`，新词条从 `256` 开始。中文按编码后的字节处理，不能把一个汉字直接当作一个编号。

解码端先读取首编号，输出其单字节内容并记为 `prev`。之后每读到编号 `k`：

1. 若 `k` 已在字典中，取出对应字符串 `entry`。
2. 若 `k` 恰好等于下一个可分配编号、字典未满且已有 `prev`，则 `entry = prev + prev[0]`。
3. 其他未定义编号报错。
4. 输出 `entry`；字典未满时加入 `prev + entry[0]`，最后令 `prev = entry`。

编码端添加“上一段 + 下一段的首字节”，解码端在读到下一段后也能添加同一词条，因此不需要传输完整字典。

例如 `ABABABA` 编码为 `65 66 256 258`。读到最后的 `258` 时，解码字典尚未保存它，但上一段为 `AB`，故可推出 `ABA`。请用逐步字典表解释这一特殊情况，不能把所有未知编号都按此处理。

## 必做任务与格式约定

| 编号 | 任务 | 完成证据 |
| --- | --- | --- |
| G1 | 任意字节编码 | 能处理 `0x00`、`0xff` 及文本编码后的字节 |
| G2 | 独立解码 | 解码器只接收编码结果，普通和特殊编号均正确 |
| G3 | 固定 16 位存储、字典容量与错误处理 | 双方约定一致，合法流可还原，非法流会报错 |
| G4 | 往返验证与大小分析 | 测试记录与实际字节数对比表 |
| G5 | 了解 Huffman 和 LZ77 | 用小例子比较三种利用冗余的方式 |
| G6 | DEFLATE 或 LZMA 二选一阅读 | 解释组成与解码流程，不要求实现 |
| G7 | 报告与 presentation | 展示正确性、实验结论及发展脉络 |

G1–G7 都需完成；G6 只选一条路线。核心 LZW 过程自行实现，不用现成压缩库代替。

双方须共同遵守以下教学格式：

- 每个编号固定为 **16 位，高字节在前、低字节在后**。
- 字典最多 **65536** 项，合法编号为 `0–65535`。满后停止添加，继续使用已有字典，不清空。
- “下一个编号”需用能表示 `65536` 的整数类型。它是状态值，不是合法输出编号。
- 每次独立编解码都重新初始化字典，无额外结束编号；空输入对应空输出。
- 首编号必须在 `0–255`；奇数字节数、非法首编号、跳过下一个编号等均须拒绝。

可用内存字节数组完成编解码和全部测试。本格式不要求兼容 GIF、ZIP 等文件格式。C/C++ 中需注意字节的无符号值及二进制读写。

## 实验要求

至少覆盖空输入、单字节、长重复串、普通文本、固定种子的随机字节、含 `0` 和 `255` 的数据，每组验证：

```text
decode(encode(data)) == data
压缩后大小占比 = 编码字节数 / 原始字节数 × 100%
```

空输入的占比记为“不适用”；低于 100% 才表示节省空间。`ABABABA` 是 7 字节，4 个 16 位编号占 8 字节，实际变大。十进制显示长度、字典运行内存不能替代编码字节数。

另构造能填满字典的数据，记录词条数确实达到 65536，检查停止添加后仍可往返；仅有“很长的输入”不能证明覆盖了容量分支。为三类非法编码各设计至少一例。注意：本格式没有校验和，不能保证检测所有数据损坏。

建议实验表包含：数据类型、生成方式/种子、原始字节数、编码字节数、大小占比、还原是否一致。解释为何重复数据和随机数据的结果不同。

## 算法发展历程

| 时间 | 思想或算法 | 它增加了什么 |
| --- | --- | --- |
| 1952 年 | Huffman 编码 | 高频符号用短码字，利用频率不均匀 |
| 1977 年 | LZ77 | 用距离与长度引用此前出现的片段 |
| 1978 年 | LZ78 | 建立逐步增长的短语字典 |
| 1984 年 | LZW | 预置单字符字典，使解码器能同步重建词条 |
| 1990 年代 | DEFLATE | 组合 LZ77 和 Huffman，RFC 1951 在 1996 年明确其格式 |
| 后续 | LZMA 等 | 将字典匹配与上下文概率、范围编码结合 |

这不是一条完全替代旧方法的直线。Huffman 和字典方法利用不同层次的冗余，现代压缩器常把它们组合。算法思想、交换格式、运行成本也不是同一个问题。

G5 请用小例子比较“高频符号用短码字”“引用此前距离与长度”“输出动态字典编号”。G6 可选：

- **DEFLATE**：LZ77 与 Huffman 分别负责什么？解压时如何先还原符号，再复制片段？
- **LZMA**：字典匹配、上下文概率模型、范围编码各起什么作用？空间收益可能付出什么计算代价？
