# 标准输入输出测试数据

每个场景分别提供 FIFO、LRU、CLOCK 三组 `.in` / `.out`，共 36 组。编号按访问次数从小到大排列，同访问次数按容量排列。每个输入独立运行一次。

`.in` 第一行是策略，第二行是容量与访问次数，第三行是访问序列。`.out` 每次访问输出一行 `hit` / `miss` 和访问后的固定槽位内容，遵守 advance README。所有文本使用 UTF-8、LF 换行。

| 文件名前缀 | 容量 c | 访问次数 n | c × n |
| --- | --- | --- | --- |
| 01_single | 1 | 1 | 1 |
| 02_repeat | 1 | 5 | 5 |
| 03_example | 3 | 7 | 21 |
| 04_belady_c3 | 3 | 12 | 36 |
| 05_belady_c4 | 4 | 12 | 48 |
| 06_all_fit | 20 | 20 | 400 |
| 07_clock_scan | 4 | 30 | 120 |
| 08_cycle | 8 | 200 | 1600 |
| 09_max_capacity | 1000 | 1000 | 1000000 |
| 10_hotspot_switch | 32 | 2000 | 64000 |
| 11_random | 64 | 10000 | 640000 |
| 12_max_length | 10 | 100000 | 1000000 |

场景涵盖单次访问、容量为 1、连续命中、统一示例、Belady 容量对照、容量大于不同页面数、CLOCK 扫描与回绕、循环超容量、热点切换、随机访问、最大容量和最大访问次数。`all_fit` 包含页面编号 0 和 2147483647。随机数据使用固定种子 20261117。

例如，将 `03_example_fifo.in` 输入待测程序，将标准输出保存后与同名 `.out` 比较。测试程序应正常退出，输出中不得包含额外提示或统计。可使用 `../run_tests.py` 自动运行全部用例并比对输出。
