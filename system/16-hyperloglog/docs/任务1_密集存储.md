# 任务 1：DenseHLL

这一阶段从 `HLL0` 出发。

HLL 的数学部分不变。

只做三件事：

1. 把寄存器从 8 位压成 6 位。
2. 支持 `dump/load`。
3. 缓存上一次 `estimate()` 的结果。

这一阶段需要完成下面这些接口。

| 内容 | 接口 |
| --- | --- |
| 6 位寄存器读写 | `get`、`set` |
| HLL 基本操作 | `add`、`estimate`、`merge` |
| 估计缓存 | `estimate`、`invalidate` |
| 序列化 | `dump`、`load` |

后面的章节会按这个顺序解释。

## 1. 为什么要做 6 位存储

HLL0 使用：

```cpp
std::vector<uint8_t> registers;
```

一个 `uint8_t` 占 8 位。

但本项目限制：

```text
4 <= p <= 14
```

`rho` 最大不会超过 61。

所以 6 位已经足够保存：

```text
0 ~ 63
```

当 `p = 12` 时：

```text
m = 4096
```

使用 `uint8_t`：

```text
4096 * 8 bit = 4096 B
```

使用 6 位：

```text
4096 * 6 bit = 3072 B
```

节省 1024 B。

## 2. 数据怎么放

所有寄存器连续放进一个字节数组。

第 `i` 个寄存器占 6 位。

它的起始位是：

```text
start_bit = i * 6
```

它所在的第一个字节是：

```text
byte_index = start_bit / 8
```

它在这个字节里的起始位置是：

```text
offset = start_bit % 8
```

例如：

```text
i = 0 -> start_bit = 0
 i = 1 -> start_bit = 6
 i = 2 -> start_bit = 12
 i = 3 -> start_bit = 18
```

第 1 个寄存器从第 6 位开始。

它会跨两个字节。

因此 `get()` 和 `set()` 都不能只看一个字节。

## 3. get(i) 要做什么

函数：

```cpp
uint8_t get(size_t i) const;
```

目标：读出第 `i` 个 6 位寄存器。

建议步骤：

```text
1. 计算 start_bit
2. 计算 byte_index
3. 计算 offset
4. 把相邻两个字节拼成一个 16 位整数
5. 右移 offset 位
6. 用 0x3F 只保留低 6 位
```

`0x3F` 的二进制是：

```text
00111111
```

所以它正好可以取出 6 位。

## 4. set(i, value) 要做什么

函数：

```cpp
void set(size_t i, uint8_t value);
```

目标：只修改第 `i` 个寄存器。

不能破坏相邻寄存器。

建议步骤：

```text
1. 计算 start_bit、byte_index、offset
2. 读出相邻两个字节
3. 生成当前寄存器的 6 位 mask
4. 先清掉原来的 6 位
5. 写入新的 6 位
6. 再拆回两个字节
```

写入前可以做：

```cpp
value &= 0x3F;
```

这样可以保证只保留低 6 位。

## 5. 为什么 data 多留 1 个字节

实现 `get/set` 时，我们统一读取：

```text
data[byte_index]
data[byte_index + 1]
```

最后一个寄存器有时并不真的跨字节。

但为了让代码保持统一，可以让内部数组多分配 1 个字节。

例如：

```cpp
std::vector<uint8_t> data(payload_bytes + 1, 0);
```

保存到文件时，不保存这一个额外字节。

它只用于内部实现。

## 6. DenseHLL::add

接口：

```cpp
void add(const std::string& value);
```

它与 `HLL0::add` 的算法完全相同。

区别只有一处：

HLL0 使用：

```text
registers[index]
```

DenseHLL 使用：

```text
get(index)
set(index, value)
```

流程：

```text
1. hash
2. 找桶
3. 算 rho
4. 如果新值更大，就 set
5. 如果真的发生修改，让缓存失效
```

## 7. estimate 缓存

`estimate()` 每次都要遍历所有寄存器。

当 `p = 12` 时，每次要读 4096 个寄存器。

如果 HLL 没有变化，第二次计算结果一定和第一次相同。

所以保存两个成员：

```cpp
bool cache_valid;
double cached_estimate;
```

逻辑如下：

```text
estimate():
    如果 cache_valid == true
        直接返回 cached_estimate

    否则
        正常计算 estimate
        保存到 cached_estimate
        cache_valid = true
```

什么时候让缓存失效？

只有寄存器真的发生修改时。

例如：

```text
add 修改了某个寄存器
merge 修改了某个寄存器
```

此时：

```text
cache_valid = false
```

如果 `add()` 加入的是重复数据，而且寄存器没变化，就不需要失效。

## 8. dump/load 的目标

我们希望：

```text
HLL -> 字节数组 -> HLL
```

恢复后，寄存器状态不变。

估计结果也应相同。

本项目只要求同一份程序中的保存和读取。

不要求与 Redis 或其他软件二进制兼容。

也不要求跨 CPU 架构保存。

## 9. Dense 文件格式

固定使用 16 字节头。

```text
0..3   "HLL1"
4      p
5      encoding
6..15  保留
16..   6 位寄存器正文
```

规定：

```text
encoding = 1 表示 dense
```

缓存只在程序运行时使用。

`dump()` 不保存缓存。

`load()` 读回后，第一次 `estimate()` 会重新计算。

这样文件格式更简单。

## 10. dump() 要做什么

接口：

```cpp
std::vector<uint8_t> dump() const;
```

建议步骤：

```text
1. 计算正文长度
2. 创建 16 + 正文长度 的数组
3. 写入 "HLL1"
4. 写 p
5. 写 encoding = 1
6. 写寄存器正文
```

## 11. load() 要做什么

接口：

```cpp
static DenseHLL load(const std::vector<uint8_t>& buf);
```

至少检查：

```text
1. buf 是否至少有 16 字节
2. 前 4 字节是否是 "HLL1"
3. encoding 是否为 1
4. p 是否在允许范围
5. 总长度是否正确
```

检查通过后：

```text
1. 创建 DenseHLL
2. 恢复正文
3. 把缓存设为无效
4. 返回对象
```

## 12. merge

接口：

```cpp
void merge(const DenseHLL& other);
```

逻辑仍然是逐寄存器取最大值。

先检查：

```text
p 是否相同
```

然后：

```text
for i = 0 .. m-1:
    current = get(i)
    incoming = other.get(i)
    if incoming > current:
        set(i, incoming)
```

只要有一个寄存器变化，就让缓存失效。

## 13. 推荐完成顺序

不要一次写完全部功能。

建议按这个顺序：

```text
1. get
2. set
3. add
4. estimate
5. merge
6. cache
7. dump
8. load
```

每完成一步就写一个小测试。

## 14. 本阶段检查内容

至少要满足：

1. 任意寄存器写入 `0~63` 后都能正确读回。
2. 修改一个寄存器不会破坏相邻寄存器。
3. DenseHLL 和 HLL0 处理同一批数据时结果一致。
4. `p = 12` 时正文大小是 3072 B。
5. `dump -> load` 后状态不变。
6. 连续两次 `estimate()` 可以使用缓存。
7. `add` 或 `merge` 修改数据后缓存失效。
8. 不同 `p` 的 HLL 不能 merge。
