# 任务 2：SparseHLL

DenseHLL 已经把一个寄存器从 8 位压到 6 位。

但数据较少时，还有一个问题。

4096 个寄存器中，可能只有很少几个不是 0。

这时保存所有 4096 个寄存器仍然很浪费。

SparseHLL 的目标是：

```text
数据少时，只保存非零寄存器。
数据多时，自动转成 DenseHLL。
```

这一阶段需要完成下面这些接口。

| 内容 | 接口 |
| --- | --- |
| 稀疏项维护 | `sparseBytes`、`updateEntry` |
| 基本操作 | `add`、`estimate` |
| 表示转换 | `promote` |
| 合并 | `merge` |
| 序列化 | `dump`、`load` |

后面的章节会逐项说明这些接口。

## 1. 先分清两个概念

HLL 的逻辑状态是：

```text
M[0], M[1], ..., M[m-1]
```

每个桶都有一个寄存器值。

SparseHLL 只是换了一种保存方法。

它没有改变 HLL 算法。

例如逻辑状态是：

```text
0, 0, 3, 0, 0, 1, 0, 0
```

稀疏状态只保存：

```text
(2, 3)
(5, 1)
```

没有保存的桶默认是 0。

## 2. 稀疏状态保存什么

建议定义一个简单结构：

```cpp
struct SparseEntry {
    uint32_t index;
    uint8_t value;
};
```

然后保存：

```cpp
std::vector<SparseEntry> entries;
```

要求 `entries` 始终按 `index` 从小到大排列。

例如：

```text
{2, 3}
{5, 1}
{9, 4}
```

这样后面编码和 merge 都更容易。

## 3. updateEntry 要做什么

输入：

```text
index
value
```

目标：把某个桶更新成更大的值。

最简单的实现不需要二分查找。

直接从头扫描即可。

步骤：

```text
1. 找到第一个 entry.index >= index 的位置
2. 如果已经存在同一个 index
       只有 value 更大时才更新
3. 如果不存在
       在这个位置插入新 entry
4. 保持 entries 有序
```

返回值可以表示：

```text
true  -> 逻辑寄存器发生变化
false -> 没有变化
```

本项目优先要求代码清楚。

不要求在这里使用复杂查找结构。

## 4. SparseHLL::add

如果当前还是 sparse：

```text
1. hash
2. 找桶
3. 算 rho
4. updateEntry
5. 如果发生变化，检查是否需要转 dense
```

如果当前已经是 dense：

```text
直接调用 DenseHLL::add
```

调用者不需要知道内部是哪种状态。

## 5. sparse 状态怎样 estimate

SparseHLL 没有完整的寄存器数组。

但仍然可以计算相同的公式。

假设：

```text
m = 4096
entries.size() = 100
```

那么空寄存器数量是：

```text
zero_count = 4096 - 100
```

每个 0 寄存器对：

```text
2^(-M[i])
```

的贡献是：

```text
2^0 = 1
```

所以可以先写：

```text
sum = zero_count
```

再遍历所有非零 entry：

```text
sum += 2^(-entry.value)
```

后面的 HLL 原始估计和小基数修正与 HLL0 完全相同。

如果当前已经 dense，直接调用：

```cpp
dense.estimate();
```

## 6. 为什么还要做稀疏字节编码

`entries` 只是程序里的内部结构。

如果 `dump()` 直接保存每个：

```text
index + value
```

每个 entry 会占很多字节。

这可能比 dense 还大。

所以 `dump()` 使用更紧凑的编码。

本项目使用三种简单指令：

```text
ZERO   00xxxxxx
XZERO  01xxxxxx yyyyyyyy
VAL    10vvvvvv
```

它们只用于保存 sparse 正文。

## 7. ZERO

格式：

```text
00xxxxxx
```

一共 1 字节。

高 2 位是：

```text
00
```

低 6 位保存：

```text
连续 0 的数量 - 1
```

所以一个 ZERO 可以表示：

```text
1 ~ 64 个连续 0
```

例如要表示 5 个 0：

```text
保存 5 - 1 = 4
```

## 8. XZERO

如果连续 0 超过 64 个，就使用 XZERO。

格式：

```text
01xxxxxx yyyyyyyy
```

一共 2 字节。

高 2 位是：

```text
01
```

剩下 14 位保存：

```text
连续 0 的数量 - 1
```

所以 XZERO 可以表示：

```text
1 ~ 16384 个连续 0
```

本项目最多有 16384 个寄存器，所以足够使用。

## 9. VAL

格式：

```text
10vvvvvv
```

一共 1 字节。

高 2 位是：

```text
10
```

低 6 位直接保存寄存器值。

稀疏状态只保存非零寄存器，所以：

```text
value 范围为 1 ~ 63
```

## 10. 一个完整编码例子

假设逻辑寄存器是：

```text
0, 0, 3, 0, 0, 0, 1, 0, 0
```

可以编码为：

```text
ZERO(2)
VAL(3)
ZERO(3)
VAL(1)
```

最后两个 0 不需要写。

原因是：

```text
没有写出的尾部寄存器默认都是 0
```

这可以继续节省空间。

## 11. sparseBytes() 要做什么

这个函数不需要真的生成字节数组。

它只计算当前 sparse 正文大约需要多少字节。

遍历有序的 `entries`。

记录：

```text
next_index
```

对每个 entry：

```text
gap = entry.index - next_index
```

如果 `gap > 0`：

```text
gap <= 64  -> 需要 1 字节 ZERO
gap > 64   -> 需要 2 字节 XZERO
```

然后当前 entry 自己还需要：

```text
1 字节 VAL
```

最后一段 0 不计算。

## 12. 什么时候转成 dense

Dense 正文大小固定为：

```text
m * 6 / 8
```

Sparse 正文大小会随着非零寄存器增多而增大。

当：

```text
sparseBytes() >= denseBytes()
```

继续使用 sparse 已经不省空间。

这时调用：

```cpp
promote();
```

## 13. promote() 要做什么

目标：

```text
SparseHLL -> DenseHLL
```

转换前后，所有逻辑寄存器必须完全相同。

建议步骤：

```text
1. 创建一个新的 DenseHLL
2. 遍历所有 entries
3. 把 entry.value 写到 entry.index
4. 清空 entries
5. 标记当前对象已经是 dense
```

转换后：

```text
estimate 不能变化
```

这是一条很重要的测试。

## 14. merge 有哪几种情况

共有四种组合。

### 情况 1：dense + dense

直接调用：

```text
DenseHLL::merge
```

### 情况 2：dense + sparse

当前对象已经是 dense。

遍历对方的非零 entries。

逐个更新当前 dense 寄存器。

### 情况 3：sparse + sparse

遍历对方的 entries。

对每一个调用：

```text
updateEntry
```

最后检查是否需要 promote。

### 情况 4：sparse + dense

最简单的做法是：

```text
1. 先把自己 promote 成 dense
2. 再调用 DenseHLL::merge
```

这样代码最清楚。

注意：

```text
merge 不能修改传入的 other
```

## 15. Sparse 的 dump 格式

仍然使用 16 字节头。

```text
0..3   "HLL1"
4      p
5      encoding
6..15  保留
16..   sparse 正文
```

规定：

```text
encoding = 0 表示 sparse
```

如果当前对象已经 dense，直接使用 DenseHLL 的 dump 格式。

## 16. Sparse 的 load

先读取：

```text
encoding
```

如果：

```text
encoding == 1
```

说明文件里是 dense。

直接调用 DenseHLL 的 load。

如果：

```text
encoding == 0
```

就按顺序读取 sparse 指令。

维护当前桶号：

```text
index
```

遇到：

```text
ZERO  -> index 前进若干位置
XZERO -> index 前进若干位置
VAL   -> 在当前 index 加入一个非零 entry，然后 index++
```

读取时至少要检查：

```text
1. 文件头完整
2. magic 正确
3. encoding 合法
4. XZERO 的第二个字节存在
5. VAL 不能为 0
6. index 不能超过 m
```

正文长度直接使用：

```text
buf.size() - 16
```

## 17. 推荐完成顺序

建议按下面顺序：

```text
1. SparseEntry
2. updateEntry
3. add
4. estimate
5. sparseBytes
6. promote
7. merge
8. dump
9. load
```

先让 sparse 状态正确工作。

再做编码和转换。

## 18. 本阶段检查内容

至少要满足：

1. 小数据时保持 sparse。
2. 小数据时占用小于 dense。
3. sparse 状态的 estimate 与 HLL0 接近一致。
4. `promote()` 前后 estimate 不变。
5. 数据增多后可以自动转 dense。
6. sparse 和 dense 都能 `dump -> load`。
7. 四种 merge 情况都正确。
8. merge 不修改 `other`。
9. 非法 sparse 数据会被拒绝。
