# Basic：目录快照与轮询监控

Basic 不是只完成在线评测中的两个 TODO。本阶段包含两个代码任务：

1. 完成 `src/monitor.cpp` 中的两个 TODO，通过快照比较的在线评测；
2. 从零编写 `src/poll_monitor.cpp`，对真实目录进行周期性扫描。

只有两项都完成，才算完成 Basic。在线评测只检查第一项，不会访问真实目录，也不会检查轮询循环。

## 任务一：完成 OJ 快照比较

代码框架位于 `src/monitor.cpp`。只能补全以下两个函数，不要修改已经提供的输入输出代码：

- `buildSnapshot`：把输入条目转换为“文件名到文件元数据”的映射；
- `diffSnapshots`：比较新旧快照，生成按文件名字典序排列的变化日志。

快照只保留 `type == 'F'` 的普通文件，必须忽略 `type == 'D'` 的子目录。变化规则如下：

| 条件 | 输出 |
| --- | --- |
| 新快照有、旧快照没有 | `CREATE <name>` |
| 旧快照有、新快照没有 | `DELETE <name>` |
| 两边都有，但大小或修改时间不同 | `MODIFY <name>` |
| 两边都有且元数据相同 | 不输出 |

重命名不作特殊识别，而是输出旧名称的 `DELETE` 和新名称的 `CREATE`。算法应达到 O((N0 + N1) log(N0 + N1)) 或更好，不能对两份快照进行嵌套线性查找。

### 输入格式

```text
N0
<name> <size> <mtime> <type>     （共 N0 行，旧快照）
N1
<name> <size> <mtime> <type>     （共 N1 行，新快照）
```

- `name` 不含空白字符，只含字母、数字、`.`、`_`、`-`，长度不超过 64；
- `size` 范围为 0 到 10^9；
- `mtime` 范围为 0 到 10^18，必须使用 64 位整数；
- `type` 为 `F` 或 `D`；
- 每份快照最多包含 100000 个条目，输入顺序不保证有序；
- 同一快照中的普通文件名不会重复。

### 输出格式

每个发生变化的普通文件输出一行，格式为 `<operation> <name>`。所有行按文件名字节序排列；没有变化时不输出任何内容。

例如：

```text
MODIFY a
DELETE b
CREATE c
```

编译和运行示例：

```bash
g++ -std=c++17 -O2 -o monitor src/monitor.cpp
./monitor < testcases/1.in
```

`testcases/` 中提供本地输入输出测试。程序读取的是文本形式的两份快照，不是真实目录。

## 任务二：从零实现真实目录轮询

本任务不提供代码骨架。请自行创建 `src/poll_monitor.cpp`，使用 C++17 标准库完成一个非递归目录监控器。

程序入口统一为：

```text
./poll_monitor <directory> <poll-count> [interval-ms]
```

- `directory`：需要监控的目录；
- `poll-count`：建立初始基线后，再执行的扫描次数，必须为正整数；
- `interval-ms`：两次扫描之间的间隔，省略时默认为 1000 毫秒，必须为正整数。

编译示例：

```bash
g++ -std=c++17 -O2 -o poll_monitor src/poll_monitor.cpp
./poll_monitor ./watch-dir 10 1000
```

### 必须自行实现的部分

1. 解析并检查命令行参数；
2. 使用 `std::filesystem::directory_iterator` 扫描指定目录；
3. 为每个直接子级普通文件记录相对文件名、大小和最后修改时间；
4. 跳过子目录、符号链接以及其他非普通文件，不递归扫描；
5. 启动时建立基准快照，不把已有文件输出为 `CREATE`；
6. 按指定间隔重复扫描，并比较相邻两次成功的快照；
7. 按文件名字典序输出 `CREATE`、`DELETE` 和 `MODIFY`；
8. 正确报告参数错误、目录不存在、目录无法读取以及扫描中的文件系统错误；
9. 只有整轮扫描成功后才能替换旧基线。扫描失败不能被当作空目录，否则会产生虚假的批量 `DELETE`。

可以复用任务一的快照比较思路，但需要自行处理 `std::filesystem::file_time_type`、真实路径和文件系统错误。程序不得创建、删除或修改被监控目录中的文件，也不要求使用多线程。

### 行为边界

- 每轮扫描只反映采样时看到的状态；
- 扫描间隔中创建后又删除的文件可能无法被发现；
- 文件大小和最后修改时间相同，不代表文件内容一定没有变化；
- 轮询不能发现纯读取操作；
- 元数据变化次数不等于实际写入次数。

## 手工验收

请使用专用测试目录，至少验证以下情况：

- 启动前已有的文件只作为基线，不输出 `CREATE`；
- 创建文件后输出 `CREATE`；
- 追加或修改文件后输出 `MODIFY`；
- 删除文件后输出 `DELETE`；
- 空目录可以正常监控；
- 子目录及其中的文件被忽略；
- 内容不变的重复扫描不输出日志；
- 非法路径或无权限目录产生错误；
- 某轮扫描失败时不产生虚假的 `DELETE`，后续成功扫描仍与上一次成功基线比较。

每个真实文件操作后至少等待两个扫描周期，再检查日志。请记录运行环境、编译及运行命令、测试操作和观察到的输出。
