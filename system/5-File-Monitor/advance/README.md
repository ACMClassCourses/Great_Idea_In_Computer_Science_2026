# Advance：Linux inotify 事件驱动监控

Advance 不提供代码骨架。学生需要从零设计并实现完整程序，建议创建：

```text
advance/src/inotify_monitor.cpp
```

不得使用 `system("inotifywait")` 或第三方监控库替代核心实现。程序必须直接调用 Linux 的 inotify API，因此需要在 Linux 或 WSL 环境中完成。

开始 Advance 前，应先完成 Basic，并能够解释轮询监控的行为和限制。

## 需要从零实现的程序

程序监控指定目录的直接子项，不要求递归。命令行形式可自行设计，但必须在提交说明中给出明确的编译、运行和退出方法。

实现至少包括以下部分：

1. 使用 `inotify_init1(IN_NONBLOCK | IN_CLOEXEC)` 创建实例；
2. 使用 `inotify_add_watch` 监听指定目录，并维护 watch descriptor 与目录路径的对应关系；
3. 使用带有限超时的 `poll` 等待事件，使程序在没有事件时仍能检查退出条件；
4. 使用 `read` 读取事件缓冲区，并正确遍历其中多条变长的 `inotify_event`；
5. 处理访问、修改、创建、删除、移入和移出事件；
6. 识别目录事件、watch 失效、监控目录被删除或移动，以及事件队列溢出；
7. 实现一种日志过滤规则；
8. 按规定聚合同一路径的连续 `MODIFY` 通知；
9. 支持有限等待或 SIGINT 退出，并在退出时冲刷聚合日志、移除 watch、关闭文件描述符。

## 必须处理的事件

watch 至少订阅：

- `IN_ACCESS`
- `IN_MODIFY`
- `IN_CREATE`
- `IN_DELETE`
- `IN_MOVED_FROM`
- `IN_MOVED_TO`
- `IN_DELETE_SELF`
- `IN_MOVE_SELF`

处理事件时还要识别 `IN_ISDIR`、`IN_IGNORED` 和 `IN_Q_OVERFLOW`。同一事件可能同时带有多个标志，必须使用位运算判断，不能把事件掩码当作单一枚举值。

一次 `read` 可能返回多条事件。每条记录的长度为 `sizeof(inotify_event) + len`，程序必须检查剩余缓冲区长度，并正确处理 `len == 0` 和名称末尾的空字符，不能用固定大小步进整个缓冲区。

## 日志和移动事件

可以沿用 Basic 的 `CREATE`、`MODIFY`、`DELETE` 格式，并为读取输出 `ACCESS`。

移动事件分别输出 `MOVED_FROM` 和 `MOVED_TO`，同时记录 cookie，以便说明同一 cookie 如何关联一对移动事件。跨越监控边界时可能只收到其中一半，不要求完整还原重命名。

## 过滤与 MODIFY 聚合

至少实现一种简单过滤规则，例如：

- 只显示 `.txt` 文件；或
- 忽略名称以 `.` 开头的条目。

过滤规则只控制日志显示，不能破坏必要的内部状态维护。

对于通过过滤的同一路径 `MODIFY` 通知，记录首次接收时间、最后接收时间和收到的通知条数。连续一秒没有新的 `MODIFY` 后，输出一条汇总并清除记录。时间判断必须使用单调时钟。程序退出时必须输出尚未完成的汇总。

聚合计数只能描述“收到的通知条数”，不能声称它等于文件真实写入次数。

## 退出与错误处理

- 程序在空闲和高频事件下都必须能够退出；
- 如果使用 SIGINT，信号处理函数只能设置 `volatile std::sig_atomic_t` 标志；
- 资源释放、输出和容器操作必须在主循环中完成；
- 正确区分 `EAGAIN`、`EINTR` 和真正的读取错误；
- 遇到 `IN_Q_OVERFLOW` 时明确提示事件可能已经丢失；
- 监控目录被删除、移走或 watch 失效时，提示原因并结束本次监控；
- 退出时移除 watch 并关闭文件描述符。

inotify 不能保证提供完整审计历史，也不提供事件对应的进程身份或读写字节数。即使最终目录状态正确，也不能据此断言中间事件没有丢失。

## 测试要求

至少测试：

- 创建、读取、追加、删除和移动文件；
- 连续多次修改同一文件；
- 一个缓冲区包含多条事件；
- 过滤规则生效；
- 聚合静默超时和退出时冲刷；
- 无事件时能够退出；
- 高频事件下能够退出；
- 监控目录自身被删除或移走；
- watch 失效和事件队列溢出的处理分支。

队列溢出难以稳定触发时，可以把事件解析和状态处理拆成函数，用人工构造的输入验证对应分支。不要假定一次编辑器保存只产生一条 `MODIFY`。
